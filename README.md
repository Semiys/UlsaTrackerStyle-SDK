# UlsaTrackerStyle SDK

Продуктовая аналитика: SDK отмечает действия в приложении, сервер сохраняет события, веб-панель показывает статистику. Первый клиент — **«Дом Коллекционера»**, Android/KMP.

## Текущее состояние

Сервер **0.4.1**, Kotlin SDK **0.2.0**, демонстрационный APK **1.2**. Для ЛР2 выделен образ **0.0.2**: один контейнер, Express, серверные шаблоны EJS и хранение в JSON. Реализация DuckDB сохранена для дальнейшего развития; в образ ЛР2 её пакет не устанавливается.

В локальной версии 0.4.1 добавлен выбор светлой, тёмной или системной темы. Палитры взяты из «Дома Коллекционера»; выбор сохраняется в браузере. Опубликованный образ ЛР2 0.0.2 пока содержит сервер 0.4.0; изменения оформления появятся в следующей публикации.

| Действие | Страница |
|---|---|
| Создать событие и получить подтверждение | `/events/new` → `POST /events` |
| Посмотреть счётчики, график и последние события | `/dashboard` |
| Получить объяснение отказа | `/error`, а также ответ на ошибочную форму |

Главная страница — `/`. На всех четырёх страницах есть название продукта и общее меню. Данные на старте не создаются.

## Запуск

Репозиторий: https://github.com/Semiys/UlsaTrackerStyle-SDK

Pull Request: https://github.com/Semiys/UlsaTrackerStyle-SDK/pull/1

Образ: https://hub.docker.com/r/semiys/ulsatrackerstyle-sdk

Команды вводятся целиком, каждая одной строкой. Порт 8080 должен быть свободен.

```bash
docker pull semiys/ulsatrackerstyle-sdk:0.0.2
docker run --rm -p 8080:8080 semiys/ulsatrackerstyle-sdk:0.0.2
```

После запуска откройте http://localhost:8080. Остановка — Ctrl+C. Docker публикует один порт компьютера 8080, сервер внутри контейнера слушает 8080. Такой запуск проверен на Intel с опубликованным тегом 0.0.2.

## Проверка запущенной ЛР2

Откройте **http://localhost:8080**. При первом запуске статистика пуста. Выберите «Отправить событие», сохраните предложенные значения: откроется панель с подтверждением и новой записью. На странице «Пример отказа» выберите «Вернуться к форме» и отправьте пустое название — сервер покажет, кто выполнял действие, какую операцию и почему она отклонена. Счётчики при отказе не увеличиваются.

Образ содержит `linux/amd64` и `linux/arm64`; Docker выбирает платформу сам. На Windows/macOS нужен Docker Desktop с Linux-контейнерами, на Linux — Docker Engine. Node.js, EJS и Express находятся внутри образа.

В ЛР2 включён локальный демонстрационный проект с **публичными учебными ключами**. Просмотр доступен сразу; форма использует подписанный токен. Этот режим предназначен для показа работы на localhost. Обычная сборка `runtime` создаёт отдельные ключи отправки и просмотра и требует ключ просмотра на панели.

## Данные и повторный запуск

События лежат в `/app/data/events.json`, настройки проекта — в `access.json`. В короткой команде выше файлы находятся в контейнере: после его остановки с `--rm` контейнер удаляется. Перезапуск работающего контейнера через Docker Desktop сохраняет его файлы.

Для разработки с сохранением данных при пересоздании используйте отдельный именованный контейнер и Docker volume. Выполните этот запуск после остановки короткой проверки:

```bash
docker run -d --name ulsa-tracker-lab2 --memory 512m --cpus 2 -p 8080:8080 --mount type=volume,source=ulsa-tracker-lab2-data,target=/app/data semiys/ulsatrackerstyle-sdk:0.0.2
```

Используйте один работающий сервер на том. Для этого именованного контейнера доступны команды:

```bash
docker stop ulsa-tracker-lab2
docker start ulsa-tracker-lab2
```

Чтобы пересоздать контейнер, остановите и удалите только контейнер, затем повторите `docker run` с тем же томом. Не удаляйте том с нужными событиями. После перезапуска откройте форму заново: токен ранее открытой формы перестаёт действовать.

Повтор того же `eventId` с тем же содержимым учитывается один раз. Изменённое содержимое с прежним ID отклоняет весь пакет. Подтверждение API отправляется после сохранения файла через временный файл, синхронизацию и переименование. Повреждённое хранилище останавливает запуск, а не обнуляет данные.

Для учебного JSON-хранилища установлен предел **10 000 событий или 16 МиБ**, очередь — **32 операции**. Это реализация для ЛР2. Миллионы клиентов потребуют другого хранения, ограничений и измерений нагрузки.

## Если порт занят

При занятом 8080 используйте 8081:

```bash
docker run --rm -p 8081:8080 semiys/ulsatrackerstyle-sdk:0.0.2
```

Также можно заменить публикацию порта на `-p 127.0.0.1:8080-8180:8080`. Docker выберет один свободный порт; адрес покажет `docker port ИМЯ_КОНТЕЙНЕРА 8080/tcp`. Выбор самого младшего номера не гарантируется. На Docker Desktop занятый обычной программой Windows порт может потребовать другого диапазона. Остальные процессы не останавливаются.

## Мобильная SDK

Kotlin/KMP SDK реализована для **Android и JVM**: ограниченная постоянная очередь, пакетная отправка в фоне, повторы и обработка подтверждений. iOS и JavaScript SDK — следующие этапы.

В «Дом Коллекционера» есть необязательная debug-интеграция. Для ЛР2 отдельно собран APK 1.2, направляющий события в демонстрационный проект. Исходники мобильного приложения и его обычные локальные настройки не менялись. APK передаётся отдельно, не добавляется в Git или образ сервера.

При подключении телефона по USB:

```bash
adb reverse tcp:8080 tcp:8080
```

Если сервер открыт на другом порту компьютера, измените второй порт. В текущей локальной проверке сервер ЛР2 находится на 18084: `adb reverse tcp:8080 tcp:18084`. После действий в приложении подождите 35–60 секунд и обновите панель. Полный сценарий — [LAB2_ANDROID.md](docs/LAB2_ANDROID.md).

## Сборка и автоматические проверки

В папке исходников:

```bash
docker build --target lab2 -t ulsatrackerstyle-sdk:0.0.2 .
docker build --target lab2-test -t ulsa-lab2-tests:0.0.2 .
docker run --rm --memory 512m --cpus 2 ulsa-lab2-tests:0.0.2
```

Проверка JSON, HTTP и страниц — 12 тестов. Полный набор также проверяет сохранённую реализацию DuckDB:

```bash
docker build --target test -t ulsa-tracker-all-tests:0.4.0 .
docker run --rm --memory 512m --cpus 2 ulsa-tracker-all-tests:0.4.0
```

Тесты используют временные данные внутри проверочного контейнера. Рабочий том к ним не подключается. Для локальной загрузки обеих платформ на Docker Desktop используйте Buildx с `--platform linux/amd64,linux/arm64 --load`.

## Сохранённая реализация DuckDB

Исходники `src/store.js` и `src/schema.sql` сохранены. Обычная сборка устанавливает DuckDB как дополнительную зависимость; режим выбирается явно:

```bash
docker build --target runtime -t ulsatrackerstyle-sdk:0.4.0 .
docker run -d --name ulsa-tracker-duckdb --memory 512m --cpus 2 -e STORAGE_BACKEND=duckdb -p 127.0.0.1:8082:8080 --mount type=volume,source=ulsa-tracker-dev-data,target=/app/data ulsatrackerstyle-sdk:0.4.0
```

Перед запуском с прежним томом остановите сервер, который уже пишет в него. Ключи обычного проекта можно посмотреть локально командой `docker exec ИМЯ_КОНТЕЙНЕРА node src/show-access.js`. Не добавляйте их в Git. Старый рабочий контейнер 0.3.0 и его события сохранены отдельно от демонстрации ЛР2.

## Публикация

ЛР1 остаётся в теге **0.0.1**. ЛР2 публикуется отдельным тегом **0.0.2**, внутренний номер сервера — **0.4.0**.

```bash
docker buildx build --platform linux/amd64,linux/arm64 --target lab2 -t semiys/ulsatrackerstyle-sdk:0.0.2 --push .
docker buildx imagetools inspect semiys/ulsatrackerstyle-sdk:0.0.2
```

В выводе нужны `linux/amd64` и `linux/arm64`. Дополнительные аттестации `unknown/unknown` не заменяют их. Не отправляйте образ одной платформы поверх общего тега.

Для ЛР2 используется ветка `codex/lab2` и Pull Request в `main`. Основная ветка остаётся без изменений до проверки PR. Ссылки и результаты публикации — [LAB2.md](docs/LAB2.md).

## Ветки для лабораторных

- `codex/lab1-fixes` — исправления документации ЛР1, PR №2.
- `codex/lab2` — код и документация ЛР2, PR №1. Исправления ЛР1 включены в эту ветку, чтобы сохранить их при следующем слиянии.
- `main` — принятые изменения. До просмотра и слияния PR основная ветка остаётся на прежнем коммите.

После проверки сначала объедините PR исправлений ЛР1, затем PR ЛР2 обычным merge, сохраняющим историю. Для следующей лабы:

```bash
git switch main
git pull --ff-only
git switch -c codex/lab3
```

Публикация образа и имя ветки — отдельные вещи: каждая сдаваемая версия имеет свой тег, например 0.0.1 и 0.0.2. Номера PR присваивает GitHub, они не обязаны совпадать с номерами лабораторных.

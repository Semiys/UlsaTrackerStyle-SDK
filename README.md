# UlsaTrackerStyle SDK

03.10.2026 название продукта исправлено с Tracer на Tracker. Имена пакета, страницы, Docker-образа и команды обновлены. Пользователь переименовал GitHub-репозиторий в `Semiys/UlsaTrackerStyle-SDK`; ссылки и локальный `origin` соответствуют новому адресу. Папка проекта пока сохраняет прежнее имя: `D:\MyTracer SDK CopyStyle`.

Сервис продуктовой аналитики с собственной SDK для мобильных приложений. Разработчик подключает библиотеку, отмечает события экранов и кнопок и просматривает статистику в веб-интерфейсе.

Текущая версия — **0.0.1**, основа ЛР1: Node.js + Express показывает первую страницу в одном контейнере. Сбор событий, DuckDB, графики и мобильная SDK пока запланированы, не реализованы.

## Решения

- Приоритет: Kotlin/KMP SDK, первая интеграция и проверка на Android в DomCollection; iOS позже.
- Сервер: Node.js + Express. Аналитическое хранилище следующего этапа: DuckDB.
- Начальный запуск: один Linux-контейнер Docker. Разделение на несколько сервисов планируется к ЛР3–4 после получения методичек.
- JavaScript SDK для сайтов — после работающего мобильного сценария.
- SDK обращается к собственному API и проектируется для использования приложения в разных магазинах; общий код KMP не ограничивает подключение только KMP-приложениями.
- Работа над отдельным `collector-transfer-service` заморожена 03.10.2026.

## Локальный запуск

Нужны GitHub Desktop (или Git) и Docker с поддержкой Linux-контейнеров. Установка Node.js, Express и DuckDB на хост для ЛР1 не нужна: Dockerfile устанавливает зависимости внутри образа.

Пользователь установил Docker Desktop на ноутбук, чтобы проверять проект локально. По текущему решению хранилище Docker остаётся на C:, исходники — на D:. [Установка, расположение данных и ограничения ресурсов](docs/DOCKER_SETUP.md). Те же команды работают на втором ПК.

В терминале открытой папки репозитория:

```bash
docker build -t ulsatrackerstyle-sdk:0.0.1 .
docker run --rm -d -p 127.0.0.1:8080-8180:8080 --name ulsa-tracker-auto ulsatrackerstyle-sdk:0.0.1
docker port ulsa-tracker-auto 8080/tcp
```

Последняя команда показывает выбранный адрес, например `127.0.0.1:8082`. Откройте его в браузере с префиксом `http://`. Docker выбирает свободный порт компьютера из диапазона 8080–8180; порт сервера внутри контейнера остаётся 8080. Так другие запущенные контейнеры не мешают старту. Диапазон не означает открытие всех 101 портов: публикуется только один выбранный порт.

Контейнер работает в фоне. Логи: `docker logs -f ulsa-tracker-auto`. Остановка: `docker stop ulsa-tracker-auto`; благодаря `--rm` остановленный контейнер удаляется. Перед повторным запуском с тем же именем остановите свой предыдущий экземпляр; для второго одновременно работающего экземпляра укажите другое `--name`.

Автовыбор реализован стандартной настройкой Docker, поэтому одинаковая команда подходит для Windows, Linux и macOS с Linux-контейнерами. Проверен сценарий занятости портов другими контейнерами. На Docker Desktop порт, занятый обычной программой Windows, может вызвать ошибку привязки: в таком случае задайте другой диапазон. Если занят весь диапазон, Docker сообщает об ошибке; другие процессы автоматически не останавливаются. Основа: [синтаксис диапазона host-портов в Docker](https://github.com/moby/moby/blob/master/daemon/builder/dockerfile/dispatchers.go).

Dockerfile использует Node.js **24.21.0**; Express **5.2.1** закреплён в `package.json`, транзитивные зависимости — в `package-lock.json`.

## Публикация для преподавателя — Intel/AMD x64 и ARM64

Публичный образ — [semiys/ulsatrackerstyle-sdk:0.0.1](https://hub.docker.com/r/semiys/ulsatrackerstyle-sdk). 04.10.2026 проверены опубликованный манифест с `linux/amd64` и `linux/arm64` и скачивание без авторизации через отдельную пустую конфигурацию Docker. Digest индекса: `sha256:e2c58257bbffeea835d8889447d2f97aa3587cf687d4eb3da18bca39e04644e6`.

Дополнительное требование преподавателя от 03.10.2026: сборка и публикация для двух архитектур. Для нашего проекта это `linux/amd64` (Intel/AMD x64) и `linux/arm64` (ARM64). Обе версии публикуются под одним тегом.

Для сборки подготовьте Buildx builder один раз:

```bash
docker buildx create --name ulsa-builder --driver docker-container --bootstrap --use
```

При последующих сборках выберите его командой `docker buildx use ulsa-builder`. Если имя уже существует, повторно создавать builder не нужно. Это служебный компонент сборки; приложение ЛР1 при запуске по-прежнему состоит из одного контейнера.

Из корня проекта выполните:

```bash
docker login
docker buildx build --platform linux/amd64,linux/arm64 -t semiys/ulsatrackerstyle-sdk:0.0.1 --push .
docker buildx imagetools inspect semiys/ulsatrackerstyle-sdk:0.0.1
```

Публикация требует прав на репозиторий Docker Hub. Установите для него публичную видимость. В выводе проверки должны присутствовать обе платформы; записи аттестаций `unknown/unknown`, если есть, не заменяют `amd64` или `arm64`.

Не заменяйте эту публикацию обычным `docker push` образа одной архитектуры с тем же тегом. Результат сборки с драйвером `docker-container` отправляется в реестр через `--push`; для запуска опубликованного образа сначала выполните `docker pull`.

После публикации преподавателю достаточно:

```bash
docker pull semiys/ulsatrackerstyle-sdk:0.0.1
docker run --rm -d -p 127.0.0.1:8080-8180:8080 --name ulsa-tracker-auto semiys/ulsatrackerstyle-sdk:0.0.1
```

Адрес страницы покажет `docker port ulsa-tracker-auto 8080/tcp`. Например, вывод `127.0.0.1:8082` означает `http://127.0.0.1:8082`. В Docker Desktop выбранный порт также виден в колонке Ports. Автовыбор задаётся при запуске, поэтому заново собирать или публиковать образ ради этой настройки не требуется.

Для обязательного фиксированного адреса можно использовать `-p 127.0.0.1:8080:8080`, если порт 8080 свободен. Внутренний порт 8080 соответствует `Dockerfile`, независимо от выбранного порта компьютера.

Git-репозиторий опубликован пользователем: [Semiys/UlsaTrackerStyle-SDK](https://github.com/Semiys/UlsaTrackerStyle-SDK). Локальная папка — `D:\MyTracer SDK CopyStyle`, ветка — `main`. Коммиты и пуш выполняет пользователь.

## Windows, Linux и macOS

Код контейнера рассчитан на Linux. На Windows и macOS он запускается через Docker Desktop с Linux-контейнерами, на Linux — через Docker Engine. Архитектура образа должна соответствовать процессору или поддерживаемой эмуляции.

Docker выбирает вариант опубликованного образа по архитектуре хоста. Windows/macOS используют Linux-контейнеры: в этом задании не создаётся отдельный образ Windows. ARM64-сборка на Intel-ноутбуке выполняется через эмуляцию Docker Desktop и может быть медленнее. Проверять каждую платформу нужно отдельно; команды приведены в [списке проверок](docs/SECOND_PC_CHECKLIST.md).

03.10.2026 проверен работающий Docker Engine, успешно собран и запущен локальный образ для `linux/amd64` и `linux/arm64`. AMD64 проверен на Intel, ARM64 — через эмуляцию Docker Desktop. Для каждой платформы проверены страница, CSS, обязательные тексты, остановка и повторный запуск. 04.10.2026 подтверждены публикация обеих архитектур и публичное скачивание; отдельный другой компьютер ещё не проверен. Результаты — в [списке проверок](docs/SECOND_PC_CHECKLIST.md). Пользователь разрешил работу с текущим хранилищем Docker на C:; перенос на D: отменён. Разрешения, ключи API и платёжные аккаунты для страницы ЛР1 не нужны.

# Docker Desktop на ноутбуке

Пользователь установил Docker Desktop и WSL самостоятельно. Агент проверил работающий Docker Engine и собрал локальный образ для amd64 и arm64. Настройки хранилища и ограничения ресурсов агентом не менялись. Дальнейший расход диска зависит от образов и кэша сборок.

## Установка

1. Скачайте Docker Desktop с [официальной страницы Windows](https://docs.docker.com/desktop/setup/install/windows-install/): вариант **x86_64 / AMD64** подходит процессору Intel i5-13500H. Windows ARM-установщик этому ноутбуку не нужен.
2. Запустите установщик. Выберите **WSL 2** как backend, если установщик предлагает выбор. При запросе компонентов Windows/перезагрузки завершите их установку.
3. Откройте Docker Desktop, прочитайте и подтвердите его условия использования. Для проекта используйте Linux-контейнеры.
4. По последнему решению пользователя от 03.10.2026 на этом ноутбуке хранилище Docker остаётся на **C:**, в стандартном расположении WSL. Перенос в `D:\DockerData` отменён. Исходники проекта остаются на D:. Если впоследствии понадобится перенос, используйте **Settings → Resources → Advanced → Disk image location**, примените изменение и дождитесь переноса и перезапуска Docker. Часть программы и служебных файлов Windows может оставаться на C:.
5. При желании отключите автоматический запуск Docker Desktop при входе в Windows и открывайте его на время работы с контейнерами.

По [документации Docker для WSL](https://docs.docker.com/desktop/features/wsl/) команды доступны из Windows-терминала; отдельный пользовательский дистрибутив Ubuntu для них не требуется. Если Docker не запускается, сначала смотрим точный текст ошибки и версии Windows/WSL; настройки виртуализации не меняем вслепую.

## Фактическое расположение данных

03.10.2026 первая сборка завершилась до обсуждавшегося переноса хранилища. Локальный образ `ulsatrackerstyle-sdk:0.0.1` содержит варианты `linux/amd64` и `linux/arm64`; установка зависимостей и проверка запуска обоих вариантов прошли без ошибок. ARM64 проверен через эмуляцию на Intel. Образ в реестр не публиковался.

При последней проверке основной диск находился в `C:\Users\sauro\AppData\Local\Docker\wsl\disk\docker_data.vhdx` и занимал около 2,26 ГБ. Пользователь разрешил сохранить это расположение и продолжить работу. Прежняя приостановка сборок и запусков до переноса на D: отменена.

WSL нужен Docker Desktop для Linux-контейнеров. Его значимость не запрещает перенос основного диска средствами Docker Desktop, но сейчас перенос не требуется. Не перемещайте и не удаляйте работающий файл VHDX вручную.

## Ошибка «Virtualization support not detected»

При диагностике ноутбука 03.10.2026 обнаружено: виртуализация прошивки включена (`VirtualizationFirmwareEnabled=true`), гипервизор не запущен, `wsl --status` и `wsl --version` сообщают, что WSL не установлен. Docker Desktop уже установлен пользователем. Состояние отдельных компонентов Windows прочитать не удалось: DISM требует административного токена, которого текущий инструмент не получил.

Для устранения этой ошибки пользователю была дана инструкция установки WSL для выбранного Docker backend:

1. Закройте Docker Desktop.
2. Откройте Пуск → PowerShell → **Запуск от имени администратора**.
3. Выполните:

```powershell
wsl --install --no-distribution
```

4. Дождитесь завершения установки, сохраните открытые работы и перезагрузите Windows.
5. Откройте Docker Desktop; проверьте `wsl --version` и `docker version` в новом терминале.

Флаг `--no-distribution` выбирает установку WSL без отдельного пользовательского дистрибутива Linux. Источник: [команды WSL Microsoft](https://learn.microsoft.com/en-us/windows/wsl/basic-commands). Docker использует собственную среду WSL. Если после перезагрузки остаётся ошибка, нужны новый текст ошибки и проверка компонентов/запуска гипервизора из административного терминала; изменения BIOS или загрузчика по общему сообщению не выполняются.

Пользователь завершил настройку: повторная проверка подтвердила работу Docker Desktop 4.93.0 и Engine 29.8.1 с WSL 2. Установка WSL, изменение компонентов Windows и перезагрузка агентом не выполнялись. Впоследствии проверен запуск контейнера приложения для amd64 и arm64; подробности — в `SECOND_PC_CHECKLIST.md`.

## Начальные ограничения ресурсов

Для ноутбука с 16 ГБ ОЗУ предлагается начать с 4 ГБ памяти и 4 логических процессоров WSL. Это ограничение, а не постоянное выделение всей памяти сервису.

В WSL 2 эти параметры относятся ко всей общей виртуальной машине WSL. Их можно настроить через приложение **WSL Settings**, если оно доступно. Альтернатива — файл `%UserProfile%\.wslconfig`: добавьте или измените параметры существующего раздела `[wsl2]`, сохранив остальные настройки:

```ini
[wsl2]
memory=4GB
processors=4
```

Файл не должен называться `.wslconfig.txt`. Для применения завершите свои работы WSL и закройте Docker Desktop, выполните `wsl --shutdown`, затем снова запустите Docker Desktop. Команда останавливает все текущие WSL-дистрибутивы.

Это стартовое предложение: если сборке не хватает памяти, лимит увеличивается по конкретной ошибке. Если мешают нагрев и параллельная работа IDE, можно снизить число процессоров. Ограничения не гарантируют отсутствие троттлинга. Основание: [настройки WSL Microsoft](https://learn.microsoft.com/en-us/windows/wsl/wsl-config).

## Проверка установки

В PowerShell:

```powershell
wsl --version
docker version
docker buildx version
```

В `docker version` должны отобразиться и Client, и Server. Если есть только Client с ошибкой соединения, дождитесь запуска Docker Desktop. Отдельно устанавливать Node.js/npm для контейнера не требуется.

## Первый локальный запуск

На этом ноутбуке используется стандартное хранилище Docker на C: по текущему решению пользователя.

```powershell
Set-Location -LiteralPath 'D:\MyTracer SDK CopyStyle'
docker build -t ulsatrackerstyle-sdk:0.0.1 .
docker run --rm -d -p 127.0.0.1:8080-8180:8080 --name ulsa-tracker-auto ulsatrackerstyle-sdk:0.0.1
docker port ulsa-tracker-auto 8080/tcp
```

Откройте показанный адрес с префиксом `http://`, например `http://127.0.0.1:8082`. Docker выбирает свободный порт из диапазона, если остальные заняты контейнерами. Контейнер работает в фоне: логи — `docker logs -f ulsa-tracker-auto`, остановка — `docker stop ulsa-tracker-auto`.

Для повседневной проверки используйте локальную сборку под архитектуру ноутбука. Для сдачи преподавателю обязательна публикация сразу **amd64 + arm64**: [команды Buildx в README](../README.md), [проверки обеих платформ](SECOND_PC_CHECKLIST.md).

Docker Desktop включает средства ARM-эмуляции. ARM-сборка на Intel может быть медленнее и сильнее загружать процессор, поэтому полную публикацию двух архитектур выполняйте при подготовке версии. Подробности — [официальная инструкция сборок нескольких платформ](https://docs.docker.com/build/building/multi-platform/).

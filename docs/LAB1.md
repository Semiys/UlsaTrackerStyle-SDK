# ЛР1 — выбор платформы и первая страница

Прочитанная методичка: [МиСПИСИТ, 7 семестр, ЛР1](https://drive.google.com/file/d/1JvjoocHsA3Ifj0icmr7WD-sj5eTdbZUo/view).

Тема аналитики согласована пользователем с преподавателем вместо сервиса переноса коллекций. [МиСПИСИТ-ИСТбд-41-Саранцев-Семён-Лаб-1](https://docs.google.com/document/d/1ciQmsvlCtriD6T8bhOo8iHmi65WRs8tIgOew1OR3ZPw/edit) подготовлен 03.10.2026 и 04.10.2026 преобразован в редактируемый документ Google Docs в папке «7 семестр → Мои отчёты». Он содержит 4 страницы и оформлен по образцу собственной ЛР1 из основной папки шестого семестра. После преобразования проверены все страницы PDF-экспорта, титульный лист, обе таблицы, Dockerfile и скриншот. Отчёт прежнего сервиса переноса коллекций сохранён отдельно.

04.10.2026 содержание отчёта обновлено: публикация обеих архитектур, скачивание без авторизации и запуск опубликованных вариантов подтверждены. 08.10.2026 команды приведены к уточнённой методичке: `docker pull` и `docker run --rm -p 8080:8080` с тегом 0.0.1. Опубликованный образ скачан без авторизации и запущен на Intel; в том же теге подтверждён ARM64. Светлый снимок сделан после точного запуска.

## Выбор способа

| Способ | Выбор | Обоснование для проекта |
|---|---|---|
| Чистый язык без фреймворка и сторонних библиотек | Нет | Для будущих HTTP API, валидации событий и работы с DuckDB пришлось бы самостоятельно создавать инфраструктуру, уже доступную в готовых инструментах. |
| Язык и отдельные библиотеки без каркаса | Нет | Вариант возможен, но HTTP-маршруты и обработку запросов удобнее организовать средствами Express. |
| Фреймворк — Node.js + Express | Да | Express предоставляет основу веб-сервера для первой страницы; в следующем этапе к ней добавятся API событий и запросы статистики. |
| Настраиваемый готовый продукт, например Matomo | Нет | Задача курса — спроектировать собственный сервис и SDK, поэтому настройка готовой аналитической платформы не раскрывает разработку наших компонентов. |

## Версии первой страницы

| Компонент | Версия | Назначение и фиксация |
|---|---|---|
| Node.js | 24.21.0 | Среда выполнения сервера, `Dockerfile` и `package.json`. |
| Express | 5.2.1 | HTTP-сервер первой страницы, `package.json` и `package-lock.json`. |

DuckDB выбран для последующего хранения аналитики. Его зависимость и конкретная версия будут добавлены при реализации БД: ЛР1 прямо требует только первую страницу без БД и без Docker Compose.

## Дополнительное требование преподавателя

03.10.2026 пользователь передал просьбу преподавателя собирать и публиковать контейнеры для Intel и ARM. Для проекта приняты `linux/amd64` и `linux/arm64`, один публичный тег с двумя вариантами образа. Это обязательная часть проверки перед сдачей. Dockerfile не фиксирует архитектуру; сборка выполняется через Buildx. Команды — в README.

В отчёте укажите результат проверки манифеста и запуска каждой платформы. Если ARM64 проверен через эмуляцию на Intel, так и напишите: это не проверка на физическом ARM-устройстве.

## Что подготовлено

- `Dockerfile`: один контейнер, порт 8080, установка из файла зависимостей.
- `package.json` и `package-lock.json`: версии пакетов.
- `src/server.js`: сервер Express.
- `public/index.html`, `public/styles.css`: название продукта, описание, версия 0.0.1 и статус разработки.
- `README.md`: сборка, публикация и команды для преподавателя с одним портом 8080:8080.
- Отчёт: титул для ИСТбд-41, две таблицы, полный Dockerfile, скриншот реально открытой страницы, ссылки, результаты локальной проверки обеих архитектур; все страницы итогового PDF-экспорта Google Docs подлежат визуальной проверке перед передачей DOCX.

## Что осталось для сдачи

1. Закоммитить и отправить текущие изменения в репозиторий [Semiys/UlsaTrackerStyle-SDK](https://github.com/Semiys/UlsaTrackerStyle-SDK); проверить доступ преподавателя к исходникам.
2. Локальные сборка и запуск уже проверены агентом для amd64 и arm64 (ARM — через эмуляцию на Intel). Пользователю проверить внешний вид страницы, узкое окно и две темы; результаты технических проверок — в `SECOND_PC_CHECKLIST.md`.
3. По возможности повторить скачивание и запуск на отдельном компьютере. На ноутбуке уже проверены публичное скачивание через пустую конфигурацию Docker, манифест обеих платформ и запуск каждого опубликованного варианта; ARM64 — через эмуляцию.

Титульные данные: группа ИСТбд-41. Остальные данные и реальный скриншот берутся из согласованного образца и нового запуска, не подставляются из отчёта прежнего сервиса.

Методички ЛР1 и ЛР2 выданы; ЛР3–7 пока не получены. Номер будущей работы в плане отражает предложение по этапам, не требование преподавателя.

## Ветка и Pull Request

Первоначальная ЛР1 была отправлена напрямую в main. Для исправлений по обновлённой методичке создана отдельная ветка `codex/lab1-fixes`; её PR показывает именно изменения документации ЛР1. История прежних коммитов сохраняется.

Для следующих работ: отдельная ветка от актуальной main → коммиты → push → PR → проверка изменений → merge → локальное переключение на main и pull → ветка следующей лабы. Перенос между версиями JSON и DuckDB согласуется с заданиями следующих работ.

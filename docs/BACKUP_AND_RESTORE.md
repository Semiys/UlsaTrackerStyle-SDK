# Резервирование и восстановление

Инструмент **0.2.0**, формат комплекта **1**. Приложение ЛР5 остаётся 0.12.0, опубликованные образы — 0.0.5. Профиль определяется по фактическим контейнерам остановленного проекта и записывается в `manifest.json`.

| Профиль | Сервисы | Сохраняемые данные |
|---|---|---|
| `lab5` | app, db, dashboard, frontend, prometheus | appdata, dbdata, grafanadata, prometheusdata |
| `monitoring-react` | Те же сервисы и monitoring-dashboard | appdata, dbdata, product_grafana_13, prometheusdata, operatordata |

Комплекты инструмента 0.1.0 без поля `profile` читаются как `monitoring-react`. Другой, неполный или неоднозначный набор сервисов отклоняется. Два профиля не преобразуются друг в друга: восстановление воспроизводит исходный вариант и его точные образы.

## Перед началом

Нужны Node.js 24, Docker с Linux-контейнерами и Compose с поддержкой `!override`. Вспомогательный образ должен быть доступен локально:

```bash
docker pull node:24.22.2-bookworm-slim
```

Запускайте служебный скрипт из checkout с инструментом. Если Docker отсутствует в PATH, задайте `DOCKER_BIN`. Каталоги назначения должны находиться вне репозитория. Родительские папки нужно создать заранее; сам каталог snapshot или восстановления должен быть новым.

Это холодное резервирование: сначала остановите исходный проект **той же комбинацией Compose-файлов, которой его запускали**. Для пятисервисного стенда ЛР5:

```bash
docker compose stop
```

Для мониторингового стенда:

```bash
docker compose -f docker-compose.yml -f docker-compose.monitoring.yml -f docker-compose.react.yml stop
```

Скрипт проверяет остановку контейнеров до и после копирования. Он не останавливает исходный проект автоматически. В Compose сохранены 60 секунд на штатное завершение ClickHouse.

Копия содержит секреты и приватные данные. Храните её вне Git и публичных папок, с ограничением доступа. SHA-256 проверяет целостность, но не заменяет шифрование и не делает чужой комплект доверенным. Копия на том же диске не защищает от потери хоста; защищённое внешнее хранение проектируется отдельно.

## Создать копию

Пример PowerShell:

```powershell
New-Item -ItemType Directory -Path "D:\Backups\UlsaTracker\2026-11-15" -Force | Out-Null
node scripts/recovery.mjs backup --project mispisit-sarantsev --output "D:\Backups\UlsaTracker\2026-11-15\snapshot"
```

На Linux/macOS укажите абсолютный путь, например `/srv/backups/ulsa/2026-11-15/snapshot`. Ключ `--without-images` подходит для локальной проверки, когда все точные образы уже есть на целевом Docker-хосте. Для переноса сохраняйте образы: это поведение по умолчанию.

В комплект входят:

- все writable-тома выбранного профиля, включая ClickHouse с `events` и `ingestion_receipts`, SQLite с аккаунтами, проектами, приложениями и хешами ключей;
- состояние Grafana и история Prometheus;
- Compose-файлы и необходимые каталоги конфигурации профиля; для мониторингового профиля — также локальные секреты;
- `.env`, если он существует;
- образы по фактическим image ID, включая вспомогательный Node;
- контрольные суммы файлов и отпечатки содержимого, ссылок, владельцев и прав файлов томов.

Read-only тома плагинов в комплект не входят: они заполняются из точного образа приложения. Пятисервисный профиль копирует `grafana` и `prometheus`; мониторинговый — `grafana`, `monitoring` и `.monitoring-secrets`. Проверяйте, что исходный стенд использует штатные конфигурации этого профиля из текущего checkout. Произвольные внешние bind-каталоги инструмент не переносит.

Исходные тома подключаются только для чтения. Если источник работает, использует неизвестные тома или ссылается на удалённый образ, копирование отклоняется. Успешный `manifest.json` создаётся только после всех проверок; частичная папка без него не считается готовой копией.

## Восстановить отдельно

```powershell
New-Item -ItemType Directory -Path "D:\RestoreChecks" -Force | Out-Null
node scripts/recovery.mjs restore --input "D:\Backups\UlsaTracker\2026-11-15\snapshot" --project ulsa-recovery-proof --directory "D:\RestoreChecks\ulsa-2026-11-15" --port 18088
```

Требуются новое имя Docker-проекта и новый рабочий каталог. Совпадение с источником, существующий проект или тома, неверные контрольные суммы, неизвестный профиль и несовместимый состав комплекта отклоняются. При ошибке частичная копия остаётся для диагностики; для новой попытки выбирайте другой каталог и имя проекта.

До извлечения проверяются архивные пути и ссылки. Файлы конфигурации переносятся в приватный каталог, недостающие образы загружаются из комплекта. Перед запуском отпечатки восстановленных томов сравниваются с исходными. Восстановление использует image ID без неявного скачивания новой версии и без сборки.

| Адрес | `lab5` | `monitoring-react` |
|---|---|---|
| Кабинет | http://127.0.0.1:18088 | http://127.0.0.1:18088 |
| Prometheus | http://127.0.0.1:18089 | http://127.0.0.1:18089 |
| Grafana оператора | Отдельного сервиса нет | http://127.0.0.1:18090 |

Нужны два или три свободных последовательных порта соответственно. Все порты копии привязаны к loopback; API и БД отдельно не публикуются. Продуктовая Grafana открывается через кабинет. Используйте `127.0.0.1`, чтобы cookie копии не смешивались с основным кабинетом на `localhost`.

Входите восстановленной учётной записью. Проверку выполняйте на синтетических данных и ключах: они должны сохранить работоспособность после восстановления. Зарегистрированные origin сайтов не меняются автоматически при переносе копии на другой адрес.

## Проверить и остановить копию

1. Проверить состояние пяти или шести сервисов и ответ `/health`.
2. Сверить проекты, приложения, UUID и число событий, включая их следы приёма.
3. Проверить вход, свою статистику, отказ чужому владельцу, Grafana и выгрузки CSV/JSON.
4. Повторить прежний пакет: число логических событий и следов не должно вырасти. Отправить новое синтетическое событие: оно должно появиться только в копии.
5. Зафиксировать длительность восстановления и точку копии для оценки RTO/RPO.

Остановить восстановленную ЛР5, сохранив данные:

```powershell
docker compose -p ulsa-recovery-proof -f "D:\RestoreChecks\ulsa-2026-11-15\docker-compose.yml" -f "D:\RestoreChecks\ulsa-2026-11-15\recovery.override.yml" stop
```

Для мониторингового профиля:

```powershell
docker compose -p ulsa-recovery-proof -f "D:\RestoreChecks\ulsa-2026-11-15\docker-compose.yml" -f "D:\RestoreChecks\ulsa-2026-11-15\docker-compose.monitoring.yml" -f "D:\RestoreChecks\ulsa-2026-11-15\docker-compose.react.yml" -f "D:\RestoreChecks\ulsa-2026-11-15\recovery.override.yml" stop
```

# Ограничение приёма событий

Версия сервиса 0.12.1 сохраняет HTTP-контракт schemaVersion 1. По умолчанию один ключ может отправить 1200 запросов за фиксированное окно 60 секунд. Значение выбрано с запасом к профилю 600 запросов в минуту; окончательная пропускная способность подтверждается отдельным измерением на конкретных ресурсах.

Для текущего профиля Docker Compose значение задаётся переменной INGEST_RATE_LIMIT_REQUESTS. Допустимы целые числа от 1 до 60000; 0 не отключает защиту, а вызывает ошибку конфигурации. После изменения пересоздайте API-контейнер. Настройка передаётся через docker-compose.monitoring.yml. Без переменной используется 1200.

При превышении бюджета сервер возвращает HTTP 429 и Retry-After. SDK сохраняет неподтверждённый пакет и ждёт перед повтором. Лимит размера тела 64 КиБ, максимум 100 событий в пакете, проверка ключа, правила Origin и ограниченная очередь операций БД остаются самостоятельными ограничениями.

Счётчик хранится в памяти одного процесса и разделяется по ключам. При нескольких API-процессах он не является общим кластерным бюджетом; для такого режима требуется общая политика ограничения. Эта настройка не подтверждает поддержку миллионов устройств.

В 0.12.0 было жёстко задано 120 запросов в минуту. Первый прогон 10 запросов/с завершился 1200 успешными ответами и 4800 HTTP 429 за 10 минут. Повышение лимита само по себе не решает задержки: в 0.12.1 сводка API также переведена с семи последовательных запросов на одну агрегацию ClickHouse, сохраняющую полные суммы, разбиения, UTC и ограничение в 100 строк разбиения.


Ожидающие соседние пакеты одного приложения объединяются максимум в 1000 событий, с коротким окном 5 мс. Одновременно допускается не более 64 неподтверждённых запросов записи. Чтение и удаление являются границами объединения: порядок уже поставленных операций сохраняется. Конфликт отклоняет весь исходный пакет. Ответы выдаются только после записи событий и следов; общая транзакция двух таблиц этим не объявляется.

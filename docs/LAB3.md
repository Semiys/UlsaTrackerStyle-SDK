# ЛР3 — постоянное хранение аналитических событий

Сервер: **0.5.0**. Образ приложения: **0.0.3**. База: **ClickHouse 26.8.26.12**, официальный образ `clickhouse/clickhouse-server:26.8.26.12`. Клиент Node.js: `@clickhouse/client` **1.12.0**.

## Состояние

Реализация и локальные проверки завершены. Образ приложения собран для `linux/amd64` и `linux/arm64`; запуск ARM проверен через эмуляцию. Образ 0.0.3 ещё не опубликован, ветка `lab3` ещё не отправлена и PR не открыт. Отчёт ЛР3 ещё не создан. Теги ЛР1 и ЛР2 не перезаписывались.

## Решение о хранении

| Задача системы | Что хранится | Хранение | Причина |
|---|---|---|---|
| Аналитика использования мобильных приложений | События, экраны, нажатия, время, проект, сеанс и свойства | ClickHouse | Аналитические запросы считают события и группируют их по времени и признакам |

Предварительный выбор DuckDB пересмотрен после трёх проверок сетевого режима Quack: запись проходила, однако присоединение заполненного каталога после пересоздания контейнера завершалось ошибкой. Подробности — [результаты прототипа](../experiments/quack/RESULTS.md). Исходная встроенная реализация DuckDB сохранена отдельно.

В методичке ClickHouse указан для аналитики больших объёмов событий. Apache AGE приведён для графовых связей; эта задача в текущие функции сервиса не входит. Apache 2.0 — лицензия ClickHouse, а не отдельная СУБД.

## Данные трёх функций

| Таблица | Назначение и поля |
|---|---|
| `events` | `project_id`, `event_id`, `session_id`, время события и получения, название, экран, платформа, версия приложения, свойства, хеш содержания |
| `schema_version` | Служебная версия схемы; не пользовательская запись |

Форма принимает название события, экран и деталь действия. Идентификаторы и время формируются автоматически; для SDK приходят в пакете v1. Проект определяется сервером по ключу. Статистика читает те же события. Отказ при ошибочной форме не создаёт записи.

Проект и сеанс пока представлены атрибутами события, отдельные таблицы для них не добавлялись. Модель коллекционных предметов мобильного приложения в аналитическую базу не переносится.

## Запуск локально

До публикации образа сначала соберите его из корня репозитория:

```bash
docker build -t semiys/ulsatrackerstyle-sdk:0.0.3 .
```

```bash
docker compose up -d
```

Откройте http://localhost:8080. На главной указана версия 0.0.3. Первый запуск с новым томом создаёт пустую схему без примеров событий. При следующих запусках записи сохраняются.

Файл `docker-compose.yml` содержит только два сервиса — `app` и `db`. Имя проекта — `mispisit-sarantsev`. У приложения указан готовый `image`, строки `build` нет. Порт 8080 открыт только у приложения. Оно подключается к `db:8123`; учебные учётные данные передаются переменными окружения. `healthcheck` базы и `service_healthy` задают порядок запуска. Данные ClickHouse лежат в `dbdata:/var/lib/clickhouse`.

Проверка сохранности:

```bash
docker compose down
```

```bash
docker compose up -d
```

Флаг `-v` удаляет том; в проверке его нет. JSON/CSV-файлы событий ЛР2 не импортируются. `access.json` приложения содержит конфигурацию ключей, а не сами события. В учебном режиме ключи стабильны после пересоздания приложения.

## Повторы и ограничения

- Один процесс приложения последовательно проверяет и записывает пакеты; очередь ограничена 32 операциями.
- Перед вставкой проверяются сохранённые ID и хеши. При конфликте весь входящий пакет отклоняется до записи новых событий.
- INSERT синхронный. ACK выдаётся после успешного ответа базы. Потерянный ответ допускает повтор с теми же ID.
- `ReplacingMergeTree` использует `(project_id, event_id)` как ключ замещения. Все чтения событий выполняются с `FINAL`, поэтому фоновые слияния не определяют правильность счётчиков.
- Ограничение одного писателя относится к логике этого MVP. Межпроцессной блокировки нет: горизонтальное масштабирование приёмников потребует отдельного решения для конфликтов ID. Поддержка миллионов пользователей не заявляется.
- Примерные и рабочие проекты не смешиваются. Фотографии и содержимое коллекции SDK не передаёт.

## Проверки

13.10.2026 прошли **21 автоматическая проверка**: 9 проверок ClickHouse и 12 проверок JSON/HTTP/страниц. Проверены сохранение и повтор, конфликт ID, потерянный ответ, отказ записи, UTC, проекты, типы свойств, ограничение детализации и логические дубликаты до фонового слияния. HTTP-проверки используют настоящий ClickHouse.

Дополнительно на Intel выполнен обычный запуск Compose: пустая база, реальная форма, повтор без увеличения счётчика, отказ HTTP 400, затем `down` и `up`. Идентификаторы обоих контейнеров изменились; событие `1117d026-b4cf-4337-b4d6-9279b8a21644` и его свойства сохранились. Отдельный Restart базы также не потребовал перезапуска приложения.

ARM64-образ приложения под эмуляцией выполнил запись и чтение с ClickHouse на Intel. Работа всей пары на физическом ARM-компьютере и база ClickHouse на ARM в этом этапе не проверялись. Физический Android-телефон также не использовался; совместимость формата SDK подтверждена HTTP-тестом.

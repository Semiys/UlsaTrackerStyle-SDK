# Проверка React-кабинета 0.11.1

Дата: 03.11.2026. Среда: Docker Desktop, Linux-контейнеры, Intel/amd64. Проверки выполняются только в проекте ulsa-react-qa с отдельными томами. Рабочие коллекции мобильного приложения, пользовательские проекты и отчёты не изменялись.

## Автоматические проверки

Исходная версия 0.10.1: 107/107, без пропусков. Окончательная версия после добавления React, JSON API и мониторинга frontend: **122/122**, без ошибок и пропусков. Production-сборка проходит проверку TypeScript.

Проверены JSON-сеансы/CSRF, изоляция двух владельцев, выдача/отзыв/замена ключей, архив, валидация, размеры запросов, общие лимиты HTML/JSON, неизменный Android HTTP-контракт, Web SDK с потерянным ACK/повтором, CORS, Grafana и SQL row policies, ограниченные метрики, периоды/часовые пояса, выгрузки, статический шлюз и ошибки upstream. Существующие тесты прежнего интерфейса сохранены.

ARM64: **24/24** проверок аккаунтов, JSON API, шлюза, метрик и инструкции SDK на окончательных исходниках под эмуляцией. Отдельно собран ARM64 frontend, на нём /console вернул HTTP 200 и production React HTML. Физического ARM-компьютера в этой проверке нет.

Frontend npm audit: 0 известных находок на момент проверки. Это не проверка всех CVE контейнерной ОС и не гарантия отсутствия уязвимостей. Остаточные ограничения прежнего аудита сохраняются.

## Проверка в браузере

- Регистрация, вход/выход, повторный вход после пересоздания контейнеров, создание проекта и приложения; прямое открытие разделов и обновление страницы.
- Замена и отзыв только тестовых ключей, архивирование и восстановление тестового проекта.
- Инструкция USB подставляет настроенный порт сервиса, включая нестандартный 18086.
- Оформленный список платформ: мышь и клавиатура.
- Полный ключ виден после создания и отсутствует после перезагрузки; остаётся маска.
- Реальная браузерная SDK: screen_view и button_click, ACK для двух записей, очередь 0.
- Grafana: 2 события, 1 сессия, 1 открытие, 1 нажатие.
- Светлая/тёмная темы; тема и timezone передаются в iframe и полную панель.
- Текущий день по умолчанию, последние 5 минут, вся история, неверная дата и JSON-выгрузка.
- Исправлены лишний перезапрос метаданных при изменении периода, потеря фокуса после применения и заголовок вкладки при асинхронной загрузке.
- На viewport 390 px, с шириной содержимого 375 px из-за scrollbar, нет горизонтального переполнения. Диалог календаря помещается, действия доступны.
- Содержимое форм и код показываются как текст; клиент не получает административные секреты.

40 запросов, 4 одновременно; 20 пакетов по 10 событий, затем те же пакеты повторно. Принято 200 новых, подтверждено 200 дубликатов, в статистике 200. Локально: суммарно около 558 мс, p50 около 35 мс, p95 около 81 мс. Это локальный короткий опыт на небольших данных, не оценка предела системы или миллиона клиентов.

## Пересоздание

QA-стенд остановлен через down без -v, затем создан повторно. В тестовом приложении до и после 200 событий. Повторный вход, проект и настройки после пересоздания проверены в браузере. Это проверка постоянных томов; восстановление из резервной копии на другом хосте ещё не выполнено.

## Отказ frontend и мониторинг

В QA остановлен только frontend. Метрика прошла 1 → 0 → 1, UlsaFrontendUnavailable достигла firing после выдержки и снялась после запуска. promtool подтвердил пять корректных правил. Все шесть сервисов в конце healthy.

При проверке обновления обнаружено, что ранее запущенный Prometheus не перечитывает изменённый bind-mounted файл правил сам. В React Compose добавлена версия конфигурации, чтобы переход пересоздавал Prometheus и загружал новое правило. После исправления проверка firing и восстановления повторена успешно. Уведомления через Alertmanager этим выпуском не добавлены.

## Короткий список для пользователя

1. Открыть тестовый кабинет, проверить меню, поля, контраст и читаемость в обеих темах.
2. Создать свой тестовый проект и Android-приложение, сохранить новый ключ.
3. Подключить debug-сборку через доступный endpoint; проверить ровно одно нажатие и соответствующие события.
4. Сверить сегодня / 5 минут / ручные даты / всю историю и выгрузить CSV/JSON.
5. На тестовом приложении проверить замену/отзыв ключа и архив/восстановление проекта.
6. Проверить после перезапуска, что список проектов и события сохранились.

## Решение об интерфейсе и объём

С данными работает разработчик/владелец приложения. SDK в мобильном приложении или сайте отправляет события; веб-кабинет показывает аналитику. Первый клиент — «Дом Коллекционера» на Android/KMP. Для преподавательского показа APK не нужен: прежние три функции доступны в браузере без регистрации.

| Вариант | Решение |
|---|---|
| Собственные SVG-графики | Убраны: методичка требует готовую аналитическую панель. |
| Metabase | Рассмотрен как конструктор аналитики, в выпуск не включён. |
| Grafana 11.4.0 | Выбрана: ClickHouse datasource, настройка файлами и дальнейший мониторинг инфраструктуры. |
| Отдельный клиентский SPA | Не требуется: Express/EJS и локальные стили сохранены. |

Регистрация, проекты, приложения, ключи, частные панели и JavaScript SDK добавлены **по решению пользователя от 23.10.2026 сверх объёма ЛР4**. Они вводят новые функции и больше экранов, чем рекомендует методичка. Эти дополнения не выдаются за обязательное задание. Прежний путь «форма → запись → статистика → отказ» сохранён. Исходники разрабатываются в main; ветка lab4 сохраняется как источник выпуска и PR.

## Данные, права и повторная доставка

- События остаются в ClickHouse. Существующий `project_id` для новых приложений содержит ID приложения (`a_…`); проект и владелец находятся в метаданных. Старый `lab3-demo` не меняется.
- В SQLite хранятся владельцы, проекты, приложения, хеши ключей, сессии и соответствие организациям Grafana. Пароли хешируются scrypt; ключ и session token в БД представлены SHA-256. Полный ключ показывается один раз.
- HttpOnly/SameSite cookie, CSRF, проверка владельца на каждом объекте. Для HTTPS включается Secure. Новые Web-приложения принимают браузерный запрос только с точного разрешённого origin. Ключ отправки не даёт права читать аналитику.
- Для владельца автоматически создаются организация Grafana и ограниченный ClickHouse reader с политикой строк по его приложениям. В панели дополнительно задан конкретный ID приложения. Шлюз не доверяет присланным браузером Authorization/org заголовкам и не открывает административные методы Grafana.
- Публичный reader ограничен `lab3-demo`, только SELECT. Приватные данные не добавляются в анонимный источник. SQL панелей использует FINAL, как и серверная статистика.
- Лимиты: пакет до 64 КБ, до 120 запросов приёма в минуту на ключ, до 30 проектов владельца и 20 приложений в проекте; очередь серверной записи ограничена. При превышении приходит отказ, а не бесконечное накопление в памяти.

Kotlin SDK и новая JS SDK сохраняют ID до ACK. Повтор принятого пакета не увеличивает логическое число событий. Архивирование проекта или отзыв ключа прекращает приём, история остаётся. JS SDK поддерживает память/опциональный localStorage, ограниченную очередь, повторы с паузой, отключение сбора; [границы доставки](../sdk/js/README.md#доставка-и-ограничения).

## Настройка Grafana и хранение

Файлы источника и публичного экрана находятся в `grafana/provisioning`. Частные экраны создаются из того же шаблона при открытии приложения владельцем. Во всех случаях источник — `db:8123`. Мастер первого входа отсутствует.

Dockerfile скачивает официальный плагин только при сборке и проверяет закреплённый SHA-256 для архитектуры. Пакет входит в app и заполняет новый том `grafanaplugins4112`; Grafana читает его без установки из сети. При переносе на другую архитектуру этот производный том создают заново из подходящего образа.

Постоянное состояние: `dbdata` — события, `appdata` — метаданные/ключи/секрет кабинета, `grafanadata` — организации и настройки Grafana. Для согласованного восстановления нужны все три. В этом выпуске проверено пересоздание app и сохранность данных; автоматические резервные копии и восстановление всей площадки ещё не реализованы.

## Первый старт ClickHouse

Проверка готовности БД использует сетевое имя `db`, чтобы не принять временный локальный сервер инициализации за рабочий. Приложение повторяет открытие только при временных сетевых ошибках, не больше 20 попыток с паузой до 2 секунд; неверные права или схема завершают запуск ошибкой сразу. Это устраняет обнаруженную гонку на совершенно пустом томе. Два дополнительных теста проверяют восстановление соединения, предел попыток и отказ на постоянную ошибку.

## Проверки

На отдельном стенде прошло **40/40 тестов, без пропусков**: прежние JSON/ClickHouse и HTTP-страницы; полный ACK и потерянный ответ; настоящий запрос каждой панели; два владельца, организации и политики БД; CSRF/чужой origin/подмена заголовков; замена ключа и архив; Android-пакет с новым ключом; JavaScript SDK с настоящим HTTP API и постоянной очередью.

В браузере проверены вход, переходы, частная Grafana, темы и размеры 390/1280 px. JS SDK действительно отправила экран и нажатие с `localhost:13000` на `localhost:18085` через браузерный CORS, оба события подтверждены. Это отдельная проверка SDK, не кнопка серверного теста.

Обе архитектуры собраны. В ARM64-образе под эмуляцией проверены Node.js, создание учётной записи в SQLite и ARM64-бинарник плагина. Полная интеграция Grafana проверена на Intel; физический ARM и новый Android APK с ключом кабинета в этот цикл не входили.

При обновлении основного стенда до кабинета сохранены **31 событие**: совпали количество и контрольная сумма `E47349349E0D6C3A` до/после (одинаковый запрос по всем полям). QA использует отдельные тома.

## Проверка публичного выпуска

Из публичной ветки lab4 получены исходники без авторизации; образ 0.0.4 скачан с пустой конфигурацией Docker. На новом пустом томе запущены app/db/dashboard без сборки. Проверены пустое состояние, версия, форма, повтор без удвоения, отказ, настоящий запрос Grafana и сохранение записи после down/up без удаления томов. Проверочный стенд использовал отдельные порты и тома; основной стенд сохранён.

## Что ещё не реализовано

Горизонтальное масштабирование приёма, общая реляционная БД метаданных для нескольких app, подтверждение почты/сброс пароля, iOS-адаптер, публикация Maven/npm, автоматическое резервирование и Kubernetes. Учебные пароли app/app и локальный HTTP нужно заменить для публичного размещения. Нагрузку в миллионы пользователей не проверяли. Существование Android/iOS записи в кабинете не означает готовность адаптера на этой платформе.

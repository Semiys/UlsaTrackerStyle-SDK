При отключённом API тест ожидаемо получил 24 HTTP 502 от шлюза. Ещё один отказ имитирован потерей успешного ответа. Эти ответы проверяют повторную доставку, а не считаются успешными отправками. Для 50 ответов HTTP 200 p50 — 36 мс, p95 — 60 мс. Это длительность HTTP-запроса, без времени ожидания пакета и простоя сервера. Максимальная наблюдённая память API по Prometheus за охватывающее прогон окно 10 минут — около 175 МиБ; она не описывает память всего Docker-стенда или многосуточный рост.

## Найденное исправление

При первом завершении временного стенда ClickHouse получил код 137, OOMKilled=false. Проверка с большим временем ожидания дала код 0. В docker-compose.yml для БД добавлен stop_grace_period: 60s. После пересоздания только тестового контейнера с тем же томом подтверждены 600 контрольных событий, а обычный `docker compose stop db` без ручного тайм-аута завершился кодом 0 примерно за 9,8 с. Это подтверждает выбранную настройку на данном стенде; незавершённые запросы под максимальной нагрузкой требуют отдельного опыта.

Основной контейнер БД ради изменения тайм-аута не пересоздавался; настройка входит в PR и применится при следующем запуске по обновлённому Compose.

## Разделение окружений

Серверные проверки и остановка API выполнялись только в восстановленном проекте `ulsa-recovery-proof` на 127.0.0.1:18088. У него отдельные тома и сети. Исходный проект не останавливался и не перезапускался этим сценарием: он уже был выключен. После завершения теста пять исходных томов прочитаны только для сверки и совпали с сохранёнными отпечатками.

Затем основной проект запущен с прежними томами специально для Android-проверки по его настроенному Wi-Fi-адресу. Новые события этой проверки и накопленная очередь записаны в действующую Android-запись. Это уже следующий этап после сверки томов, поэтому неизменность серверной истории после Android-теста не утверждается.

Телефонные тесты запускались в существующем `ru.semius.domcollection.physicaltest`; SHA-256 его APK и инструментального пакета совпали с локальными артефактами. Личная установка `ru.semius.domcollection` не переустанавливалась. ADB использовался для запуска тестов и чтения результатов; `adb reverse` отсутствовал, сами события передавались по Wi-Fi. Мобильные исходники и local.properties не менялись.

После проверки временный восстановленный стенд остановлен с сохранением томов. Основной кабинет остаётся запущенным на http://localhost:8080.

## Повтор серверного сценария

Нужны уже восстановленная одноимённая копия с шестью запущенными сервисами, Node 24 и Docker CLI. Исходный `mispisit-sarantsev` должен быть остановлен. Сценарий намеренно принимает только адрес 127.0.0.1:18088, проверяет метки контейнеров, каталог проекта и loopback-привязки; он останавливает только API этой копии. Не используйте его для рабочего сервера.

Из корня репозитория в PowerShell:

```powershell
$env:DISPOSABLE_QA = '1'
$env:FRONTEND_TEST_URL = 'http://127.0.0.1:18088'
$env:RECOVERY_QA_DIRECTORY = 'D:\RestoreChecks\ulsa-2026-11-07'
$env:QA_OUTPUT_DIRECTORY = 'D:\RestoreChecks\qa-results-2026-11-09'
node scripts/verify-sdk-stability.mjs
```

Замените пути на каталоги своей восстановленной копии и результатов. Если Docker отсутствует в PATH, задайте полный путь через DOCKER_BIN. Проверка занимает около пяти минут и создаёт собственного синтетического владельца, проект и приложение только в копии. В случае аварии контроллера проверьте состояние её API; исходные тома удалять не нужно.

## Границы и оставшиеся проверки

- Настоящая JS SDK работала в Node с сохраняемым между экземплярами адаптером localStorage в памяти. Проверено восстановление клиента, но не авария браузерного процесса, очистка хранилища или отключение питания.
- Один клиент и умеренная скорость не доказывают поддержку миллионов пользователей. Отдельно нужны ступенчатая нагрузка, пределы очередей, длительный прогон и остановка БД/диска.
- Android проверен на существующем тестовом APK от 07.11.2026. Пересборка текущих параллельно изменяемых мобильных исходников, Release и iOS в этот прогон не входят. SDK в Release по прежней конфигурации отключён.
- Восстановление на другом хосте и ARM64, расписание и защищённое внешнее хранение копий ещё не проверены.
- Отложенные обновления инфраструктуры этим тестом не выполнялись. Ранее отмеченный security-patch ClickHouse остаётся обязательным пунктом перед публичным развёртыванием.

Полные логи, отпечатки личных данных и закрытые настройки хранятся вне Git. В репозиторий включены только эта сводка и воспроизводимый серверный сценарий.

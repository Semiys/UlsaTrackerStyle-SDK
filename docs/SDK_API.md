# Проект мобильной SDK

**Интерфейс и правила спроектированы; библиотеки в коде пока нет.** Дата: 04.10.2026. Kotlin/KMP, Android первым; iOS и JavaScript-клиент позже. Серверный [контракт](EVENT_CONTRACT.md) реализован.

## Подключение и методы

Разработчик запускает сервер, получает ключ приёма, подключает библиотеку, один раз создаёт экземпляр и явно отмечает полезные действия. Ключ просмотра остаётся у владельца проекта.

Предлагаемый Kotlin-интерфейс — **не готовый код для подключения**:

```kotlin
val tracker = UlsaTracker.create(
    config = TrackerConfig(
        endpoint = "https://analytics.example.com",
        ingestKey = "ключ-приёма-проекта",
        appVersion = "1.0.0"
    ),
    platform = androidPlatform(applicationContext)
)
tracker.screen("collection")
tracker.click(button = "add_model", screen = "collection")

// После успешной записи модели, отдельно от нажатия.
tracker.track(
    name = "action_success",
    screen = "add_model",
    properties = mapOf("action" to "model_saved")
)
tracker.flush()
tracker.setCollectionEnabled(false)
```

| Метод | Назначение |
|---|---|
| `create(config, platform)` | Один экземпляр, часы/UUID, хранилище, HTTP |
| `track(name, screen, properties)` | Проверить и поставить событие в очередь; сеть не блокирует UI |
| `screen(name)` | Записать `screen_view` |
| `click(button, screen)` | Записать `button_click` со свойством `button` |
| `flush()` | Запросить фоновую отправку, без обещания немедленной доставки |
| `setCollectionEnabled(enabled)` | Выключить сбор, очистить неотправленные события; при включении новая сессия |
| `close()` | Остановить экземпляр, освободить ресурсы; очередь остаётся в постоянном хранилище |

Ядро KMP: модель, валидация, очередь, повторы. Платформенные части: хранилище, HTTP, жизненный цикл. Обычное Android-приложение сможет подключить SDK без перехода целиком на KMP. Зависимости и точные Kotlin-типы закрепим при реализации.

Для локального Android нужен доступный телефону адрес компьютера и разрешённый в debug HTTP; `localhost` на телефоне — сам телефон. Продакшен использует HTTPS. Сетевую настройку проверим при интеграции.

## Стартовые правила доставки — предстоит реализовать

- UUID, UTC-время и свойства фиксируются один раз; повторы их не меняют.
- Новая сессия при запуске процесса и возвращении после 30 минут в фоне. Показ экрана фиксируется при открытии, не при каждой рекомпозиции Compose.
- Постоянная очередь до 1000 событий и до 7 суток. При переполнении удаляются самые старые неотправленные события; число удалений доступно в диагностике.
- Пакет до 20 событий, меньше 64 КиБ; отправка при заполнении или каждые 30 секунд в активном приложении. Уход в фон запрашивает отправку без гарантии завершения.
- Один HTTP-запрос одновременно; диск и сеть вне главного потока. После остановки нет бесконечных таймеров.
- Только HTTP 200 и корректные `acknowledgedEventIds` позволяют удалить подтверждённые записи.
- Сеть/429/временные ошибки: растущая задержка со случайным разбросом, учёт `Retry-After`, ограниченное число попыток за цикл. Пакет остаётся до следующего цикла/запуска, в пределах очереди.
- 400/409: диагностика и изоляция ошибочного события; исправные не должны застревать за ним. Нельзя молча менять ID.
- 401 приостанавливает отправку до исправления настройки; 413 уменьшает пакет.
- Выключение сбора прекращает создание/отправку; уже сохранённые на сервере события этим методом не удаляются.

Проверяем отсутствие сети, закрытие приложения, перезапуск с очередью, потерянный ответ после COMMIT, переполнение и выключение сбора. План не является уже доказанной доставкой при любых ограничениях ОС.

## Первая интеграция в «Дом Коллекционера»

1. `screen_view`: коллекция, статистика, профиль.
2. `button_click`: `add_model`, `save_model`, `open_filters`.
3. `action_success` со свойством `action: model_saved` после успешной локальной записи.

Название модели, цена, фото, заметки и строка поиска не отправляются. SDK не мешает сохранению и навигации при недоступном сервере. Повторное нажатие заблокированной кнопки не означает успешное сохранение.

Откладываем автоматический захват всех касаний, рекламные ID, распознавание пользователя между устройствами, удержание/воронки, скролл на каждом пикселе, публикацию библиотеки в реестре и iOS-проверки. Сначала реальное действие и надёжная доставка.

# Мобильная SDK 0.2.0

Реализованы общее Kotlin/KMP ядро, Android-адаптер и JVM-адаптер. iOS и JavaScript позже. Серверный [контракт v1](EVENT_CONTRACT.md) реализован. Подключение и сборка — [README SDK](../sdk/kotlin/README.md), проверки телефона — [SDK_CHECKLIST.md](SDK_CHECKLIST.md).

## Подключение и методы

Разработчик запускает сервер, получает ключ приёма, подключает библиотеку, один раз создаёт экземпляр и явно отмечает полезные действия. Ключ просмотра остаётся у владельца проекта.

Создавать один экземпляр в `Application.onCreate`, до запуска Activity:

```kotlin
val tracker = createAndroidTracker(
    context = this,
    config = TrackerConfig(
        endpoint = "https://analytics.example.com",
        ingestKey = "ключ-приёма-проекта",
        appVersion = "1.0.0"
    )
)
tracker.screen("collection")
tracker.click(button = "add_model", screen = "collection")

// После успешной записи модели, отдельно от нажатия.
tracker.track(
    name = "action_success",
    screen = "add_model",
    properties = mapOf("action" to "model_saved")
)
tracker.flush()
tracker.setCollectionEnabled(false)
```

| Метод | Назначение |
|---|---|
| `createAndroidTracker(context, config)` | Android-хранилище, HTTP, жизненный цикл |
| `createJvmTracker(config, storageDirectory, platform = "web")` | JVM-клиент; жизненный цикл вызывается явно |
| `UlsaTracker.create(config, storage, transport, platform)` | Ядро с пользовательскими адаптерами |
| `track(name, screen, properties): Boolean` | Проверить и поставить команду в ограниченную входную очередь |
| `screen(name)` | Записать `screen_view` |
| `click(button, screen)` | Записать `button_click` со свойством `button` |
| `flush()` | Запросить фоновую отправку, без обещания немедленной доставки |
| `setCollectionEnabled(enabled)` | Выключить сбор, очистить неотправленные события; при включении новая сессия |
| `onForeground()` / `onBackground()` | На Android вызывается адаптером |
| `suspend close()` | Остановить экземпляр, освободить ресурсы; очередь остаётся в постоянном хранилище |
| `status: StateFlow<TrackerStatus>` | Готовность хранилища, очередь, отправка, потери, отклонения и тип последней ошибки |

Ядро KMP: модель, валидация, очередь, повторы. Платформенные части: хранилище, HTTP, жизненный цикл. Обычное Android-приложение подключает SDK без перехода целиком на KMP. Имена событий/экранов: `^[a-z][a-z0-9_]{0,63}$`. Свойства — до 16 пар с такими же именами, значения `String`, конечное число, `Boolean` или `null`; вложенные объекты и списки не принимаются.

`track() == true` означает принятие команды в память SDK. Это **не подтверждение записи на диск или на сервер**. Запись асинхронная; аварийная остановка до неё может потерять событие. `ready` означает готовность журнала. Ошибки диска и переполнение видны в `status`; ответы сервера, коллекция и ключи не пишутся в логи SDK.

Для локального Android нужен доступный телефону адрес компьютера и разрешённый в debug HTTP; `localhost` на телефоне — сам телефон. USB `adb reverse` описан в README SDK. По умолчанию только HTTPS, адрес без пути, query и встроенных логина/пароля; `allowHttp = true` предназначен для локальной разработки. HTTP-редиректы отключены.

## Реализованные правила доставки

- UUID, UTC-время и свойства фиксируются один раз; повторы их не меняют.
- Новая сессия при запуске процесса и возвращении после 30 минут в фоне. Показ экрана фиксируется при открытии, не при каждой рекомпозиции Compose.
- Постоянная очередь до 1000 событий и до 7 суток. При переполнении удаляются самые старые неотправленные события; число удалений доступно в диагностике.
- Пакет до 20 событий и 60 КиБ; отправка при заполнении или каждые 30 секунд в активном приложении. Уход в фон запрашивает отправку без гарантии завершения.
- Один HTTP-запрос одновременно; диск и сеть вне главного потока. После остановки нет бесконечных таймеров.
- Только HTTP 200 с правильными версией, счётчиками и полным набором `acknowledgedEventIds` позволяет удалить записи. Удаление также сохраняется на диск.
- Сеть/429/5xx: растущая задержка с разбросом, `Retry-After` в секундах или HTTP-дате, до трёх автоматических попыток за цикл. Многократный `flush()` не обходит cooldown. Пакет остаётся до следующего цикла/запуска, в пределах очереди.
- 400/409: изоляция ошибочной записи по индексу; без индекса пакет разбивается. Неподходящая запись удаляется с увеличением `rejected`; ID не подменяется.
- 401/403 приостанавливает отправку до исправления настройки; 413 уменьшает пакет. Неизвестный ответ или неверный ACK сохраняет очередь.
- Выключение сбора запрещает новые события, отменяет отправку, очищает очередь и сохраняет выбор. Уже принятые сервером события не удаляются; запрос, принятый до отмены, отозвать нельзя.
- Android: атомарный файловый журнал в `noBackupFilesDir`, синхронизация записи и блокировка второго владельца. Журнал переписывается при изменении очереди; влияние на реальный телефон ещё предстоит измерить.
- Входной канал до 256 команд: при перегрузке `track()` возвращает `false` и увеличивает счётчик потерь.
- Повреждённый/неизвестный журнал блокирует запись и доставку, сохраняя исходный файл. Явное выключение сбора разрешает очистить его.

Эти сценарии покрываются тестами ядра/адаптеров на JVM; потерянный ответ после серверной записи проверяется отдельным Docker-тестом. Пользователь подтвердил получение первых Android-событий на физическом телефоне 05.10.2026. Проверки кликов/успехов, доставки после отсутствия связи, перезапуска и влияния на производительность остаются ручными.

## Первая интеграция в «Дом Коллекционера»

1. `screen_view`: коллекция, статистика, профиль.
2. `button_click`: `add_model`, `save_model`, `open_filters`.
3. `action_success` после успешной БД-записи: `action: model_saved` или `model_updated`.

Подключение необязательно: путь SDK задаётся локально через Gradle composite build. Без пути используется пустой адаптер. `commonMain` приложения зависит только от своего интерфейса `ProductEventTracker`; зависимость SDK добавлена в Android-модуль. iOS использует пустой адаптер.

Включён только локальный **debug** с настроенными endpoint/ingestKey. Release имеет пустые поля локального ключа и выключенную продуктовую аналитику. Существующий Tracer для сбоев и его согласие не изменены. Перед публичным включением новой аналитики ещё нужны соответствующие настройки/согласие и проверка устройства.

Название модели, цена, фото, заметки и строка поиска не отправляются. SDK не мешает сохранению и навигации при недоступном сервере. Повторное нажатие заблокированной кнопки не означает успешное сохранение.

Откладываем автоматический захват всех касаний, рекламные ID, распознавание пользователя между устройствами, удержание/воронки, скролл на каждом пикселе, публикацию библиотеки в реестре и iOS-проверки. Сначала реальное действие и надёжная доставка.

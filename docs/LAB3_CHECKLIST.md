# Ручные проверки ЛР3

Версии: образ 0.0.3, сервер 0.5.0, ClickHouse 26.8.26.12. Порядок сборки и запуска — [LAB3.md](LAB3.md). Текущий демонстрационный том уже содержит проверочную запись; это ожидаемо после теста сохранности.

1. **Запуск.** `docker compose up -d` поднимает `app` и `db`. На http://localhost:8080 видна версия 0.0.3. На `/health` — `storage: clickhouse`.
2. **Новая база.** На отдельном новом томе статистика пуста. Повторный запуск существующего тома сохраняет прежние записи. Для проверки нового тома остановите текущий проект через `docker compose down`, затем используйте `docker compose -p mispisit-sarantsev-lab3-manual up -d`. Для последующих команд этой проверки сохраняйте то же `-p`.
3. **Запись.** Отправьте корректное событие через форму. Открывается статистика с подтверждением, счётчик увеличивается на 1, запись видна в последних событиях.
4. **Повтор формы.** Вернитесь к той же форме и повторите отправку. Счётчик не увеличивается. Новое открытие формы создаёт новый ID — это уже другое событие.
5. **Отказ.** Отправьте пустое название. Видна причина отказа, число событий остаётся прежним.
6. **Разные действия.** Отправьте `screen_view`, `button_click`, `action_success`. Они изменяют соответствующие счётчики и группы. Свойство действия не считается названием кнопки.
7. **Период и темы.** Переключите 7/30 дней, светлую/тёмную тему и обновите страницу. Выбор темы сохраняется. Проверьте ширину телефона и ПК.
8. **Пересоздание.** Запомните ID события. Выполните `docker compose down`, затем `docker compose up -d`. На том же проекте событие и ID сохранились. Для отдельного ручного проекта добавляйте `-p mispisit-sarantsev-lab3-manual` в обе команды. Флаг `-v` не используйте.
9. **Перезапуск базы.** Выполните `docker compose restart db`, дождитесь состояния healthy через `docker compose ps` и обновите статистику. Данные доступны, приложение не пришлось пересоздавать.
10. **Доступ базы.** В Compose у `db` нет `ports`; опубликован только 8080 приложения. `8123/tcp` без адреса хоста в Docker Desktop означает внутренний порт.
11. **SDK по желанию.** Для демонстрационного APK 1.2 выполните `adb reverse tcp:8080 tcp:8080`, откройте приложение и перейдите между вкладками. Через 35–60 секунд проверьте Android-события. Этот физический сценарий ещё не проверен в блоке ЛР3.

Основные проверки выполнены автоматически и через HTTP; список выше предназначен для самостоятельного просмотра интерфейса. Проверочные события в приложении коллекции создавать необязательно для сдачи ЛР3: форма сервиса показывает все три функции.

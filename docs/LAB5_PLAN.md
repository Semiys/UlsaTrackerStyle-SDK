## Надёжность и границы

ClickHouse не даёт общей транзакции двум INSERT. Если запись исходника прошла, а следа — нет, ACK не отправляется. Повтор с тем же eventId восстанавливает след, не создавая второго исходного события; это проверяется отдельно. Повтор нормального пакета не увеличивает число логических следов. Удаление приложения очищает обе таблицы. Чтение публичного состояния ограничено демонстрационным проектом; приватные панели сохраняют row policies.

Таблица создаётся CREATE TABLE IF NOT EXISTS при запуске, как в ЛР3. Инструмент миграций и изменение прежних столбцов не вводятся. История до появления следов автоматически не выдумывается.

PR №7 с резервированием остаётся отдельным и не объединяется автоматически. ЛР5 основана на main; однострочное увеличение stop_grace_period БД перенесено как проверенное исправление завершения.

## Порядок

1. Реализация таблицы, JSON API, всех публичных страниц на React и метрик.
2. Проверки пустого состояния, одной записи, повторов, отказа, частичного сбоя и изоляции на отдельном стенде.
3. Снимки светлого интерфейса до/после; настоящий запрос Grafana и счётчик Prometheus.
4. Публикация нового 0.0.5 без изменения старых тегов, PR ветки lab5 и проверка анонимного запуска из неё.
5. Отчёт по образцу ЛР4 и повторная сверка с каждым требованием методички.

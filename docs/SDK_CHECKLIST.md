# Ручные проверки Android SDK 0.2.0

05.10.2026 пользователь подтвердил на телефоне получение первых событий в панели. Проверки плохой сети, перезапуска и влияния на устройство ещё остаются ручными. Инструкция подключения/команды — [README SDK](../sdk/kotlin/README.md).

## Подготовка

1. Docker-контейнер `ulsa-tracker-dev` запущен; откройте `/dashboard` и введите его `readKey`.
2. В `local.properties` мобильного проекта заданы `ulsaTracker.sdkPath`, endpoint и **ingestKey этого же проекта**. После изменения пути — Gradle Sync. Ключи не добавляйте в Git.
3. Установите debug APK, подключите USB reverse к фактическому порту Docker. На ноутбуке endpoint настроен на `http://127.0.0.1:8080`.
4. Перед каждым сценарием запишите текущие счётчики. Данные других проверок остаются; проверяйте приращение. После действий подождите 35–60 секунд и нажмите «Обновить» на dashboard. При недоступном сервере доставка откладывается.

Панель сервера 0.3.0 показывает типы событий, открытия экранов, кнопки и успешные действия отдельно. «Открытия экранов» считает только `screen_view`; одноимённые кнопки на разных экранах — разные строки. Сессии не являются уникальными пользователями. Проверки панели — [DASHBOARD_CHECKLIST.md](DASHBOARD_CHECKLIST.md).

| 13 | Свернуть и сразу вернуть приложение | Работа UI не нарушена, короткий фон не начинает новую сессию. Счётчик сессий зависит от остальных тестов/устройств |
| 14 | Оставить приложение в фоне >30 минут и вернуться, затем совершить действие | Новое действие получает новую сессию; старые queued-события сохраняют свою |
| 15 | При недоступном сервере проверить фото, импорт/экспорт ZIP, изменение модели и тему | Прежние функции работают. Это также проверяет совместимость общих зависимостей после подключения SDK |
| 16 | Пользоваться на Redmi/Tecno несколько минут, сравнить с обычной сборкой | Нет зависания UI на отправке или заметного ухудшения прокрутки. Записать модель телефона и конкретный сценарий, если появились лаги |

Для остановки контейнера: `docker stop ulsa-tracker-dev`. При запуске по текущему README без `--rm` восстановите его командой `docker start ulsa-tracker-dev` или кнопкой в Docker Desktop; не удаляйте том. Если старый контейнер был создан с `--rm`, повторите `docker run` с тем же томом. Отключение интернета телефона при USB reverse не всегда выключает локальную связь с сервером, поэтому надёжнее остановить Docker.

Force stop сразу после нажатия может потерять ещё не записанную команду. Не требуется обещать доставку такого события. После восстановления сети/сервера учитывайте текущую задержку повторов; перезапуск приложения начинает новый цикл.

## Что проверяется автоматически отдельно от телефона

- Запись в очередь перед HTTP, корректный/неверный ACK, потерянный ответ и повтор с теми же ID.
- Диск: атомарное обновление, повторное открытие и запрет двух владельцев.
- 429/Retry-After, ограничение попыток и отсутствие обхода задержки через flush.
- Ошибочные события, переполнение/срок, opt out с очисткой и сохранением выбора, остановка таймера, повреждённая схема журнала.
- Реальный Docker API: после двух событий и потерянного ответа повтор не увеличивает счётчик выше двух.

Opt out есть в API библиотеки; пользовательского переключателя продуктовой аналитики в приложении пока нет, поскольку интеграция только локальная debug. Public release отправку новой аналитики не включает. Проверки телефона, физического ARM, iOS и измерения нагрузки ещё не выполнены.

## Выполнено на компьютере 04.10.2026

- **18/18 SDK-тестов** прошли без пропусков: 12 ядра, 4 транспорта, файловое хранилище и реальный Docker API. Отдельно проверяется приход событий до обработки ACK: подтверждённые записи не отправляются заново без причины.
- SDK собрана в Android AAR и JVM JAR. Debug APK «Дом Коллекционера» и APK существующих Android-тестов собраны. Инструментальные тесты на устройстве не запускались.
- Android проект компилируется без локального checkout SDK, с пустым адаптером; проверена release-компиляция с SDK и без неё. В release BuildConfig локальные endpoint/key пустые, сбор выключен.
- Локальный серверный образ 0.2.0 собран для `linux/amd64` и `linux/arm64`; **14/14 серверных тестов на каждой архитектуре** прошли. ARM — эмуляция на Intel.
- Локальный просмотр обновлён: `http://127.0.0.1:8080/dashboard`. Рабочий том `ulsa-tracker-dev-data`, ключи и счётчик сохранены; на момент обновления событий было 0. Временный проект теста SDK удалён.

# ЛР2 — три связанные функции

Дата реализации: 06.10.2026. Методичка: [«МиСПИСиТ-2026-ИСТбд-4-Лаб-2-Три-функции»](https://drive.google.com/file/d/1yxsDaajdvutPjsiK8gpJvRHLBgOVzM3B/view). Исходный документ не изменялся.

## Выбранный объём

Один контейнер Node.js + Express, серверный шаблонизатор EJS, четыре связанные страницы. События хранятся в JSON: Express запускается без БД, поэтому для ЛР2 используется предусмотренное методичкой файловое хранение. DuckDB сохранена как отдельная реализация для следующих этапов.

Три функции образуют цепочку: разработчик отправляет действие, проверяет его в статистике, получает объяснение при ошибочных данных. Это основные операции сервиса аналитики, которые можно показать и через сайт, и через мобильную SDK.

## Функции

| Действие | Кто выполняет | Результат | Адрес |
|---|---|---|---|
| Создать событие | Разработчик через форму; приложение через SDK | Проверка, сохранение, подтверждение; повтор ID не увеличивает счётчик | `/events/new`, `POST /events`, `POST /api/v1/events` |
| Посмотреть данные | Владелец проекта; в локальном режиме ЛР2 — пользователь демонстрации | Счётчики, дневной график, группы событий, последние записи | `/dashboard` |
| Получить объяснение отказа | Отправитель ошибочной формы | Кто пытался выполнить действие, операция, причина и поле ошибки; данные не записываются | `/error`, ответ `POST /events` |

Главная `/` содержит описание и переходы, отдельной функцией не считается. Меню всех страниц ведёт ко всем действиям и на главную. Неизвестный маршрут даёт HTTP 404 с оформленным объяснением.

## Структура и роли

```text
src/
  server.js        запуск, завершение сервера, выбор хранилища
  app.js           Express, API, шаблоны, обработка ошибок
  pages.js         формы, проверка токена, просмотр и отказ
  events.js        общий формат событий и проверка пакетов
  config.js        настройки проекта, ключи, режим демонстрации
  storage.js       выбор JSON или DuckDB
  json-store.js    файловое хранение ЛР2 и агрегаты
  store.js        сохранённая реализация DuckDB
  schema.sql      сохранённая схема DuckDB
views/
  index.ejs       главная
  event-form.ejs  создание события
  dashboard.ejs   просмотр данных
  error.ejs       объяснение отказа
  partials/       общие шапка, меню и подвал
public/           стили и клиентское обновление панели
test/             проверки API, страниц, JSON и DuckDB
sdk/kotlin/       очередь и отправка событий Android/JVM
docs/             инструкции, контракт и проверки
Dockerfile        цели lab2, lab2-test, runtime, test
```

Данные `/app/data/events.json` и настройки `/app/data/access.json` создаются в каталоге данных контейнера; при подключённом Docker volume сохраняются в нём. В Git и образ они не попадают. Секреты обычного проекта остаются в томе; ключи локальной демонстрации намеренно публичны и не дают административных прав.

## Ограничения хранения

JSON обслуживает один процесс и один том. Перед подтверждением используется временный файл, синхронизация и переименование. Запись пакета целиком принимается или отклоняется; изменённое событие с прежним ID не заменяет существующее. Повреждённый файл вызывает отказ запуска.

Предел — 10 000 событий или 16 МиБ; очередь операций — 32. Обработки миллионов клиентов эта версия не обещает. Переход к нескольким сервисам и аналитической БД будет согласован с будущими методичками; одной смены расширения файла для масштабирования недостаточно.

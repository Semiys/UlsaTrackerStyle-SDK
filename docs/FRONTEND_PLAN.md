# План перехода кабинета на React

Дата решения: 24.10.2026.
Статус: выбран следующий стек и порядок перехода; начало переноса отложено по решению пользователя от 24.10.2026 до получения методички ЛР5 либо отдельного решения продолжить раньше, когда будет доступен лимит работы.

## Решение и приоритет

Будущий фронтенд кабинета UlsaTrackerStyle SDK: **React + TypeScript + Vite**.
React отвечает за компоненты и состояние интерфейса, TypeScript — за типы и контракты данных, Vite — за разработку и сборку. Версии зависимостей закрепляются в начале реализации и в lockfile; сервер разработки Vite не используется для рабочего развёртывания.

Переход планируется ближайшим отдельным этапом после завершения ЛР4, до добавления крупных новых функций кабинета. Причина раннего перехода — планы на связанные фильтры, настройки отчётов, воронки и переиспользуемые компоненты. Переписывание интерфейса само по себе не увеличивает пропускную способность приёма событий. Порядок инфраструктурных лабораторных уточняется по их методичкам; перенос не считается уже выполненным заданием ЛР5.

Проверенный выпуск ЛР4 остаётся воспроизводимым в ветке lab4 и образе 0.0.4. В текущем работающем интерфейсе используются Express/EJS, CSS и обычный JavaScript. Эта заметка фиксирует будущее решение, а не наличие React в выпущенном кабинете.

## Границы переноса

- Переносится веб-кабинет: регистрация и вход, проекты, приложения, ключи, подключение SDK, настройки и экран статистики.
- Node.js и Express продолжают обслуживать серверную логику. Для кабинета проектируется отдельный JSON API, сохраняющий серверную проверку сеансов и прав владельца.
- Контракт событий v1 для Kotlin и JavaScript SDK сохраняется; замена фронтенда не требует менять установленные мобильные клиенты.
- Готовые графики остаются в Grafana. React управляет выбором приложения, периодом и оболочкой статистики. Собственные визуализации рассматриваются отдельно при появлении конкретной задачи.
- Сохраняется существующая визуальная система: светлая и тёмная темы, цвета, оформленные контролы и адаптация к телефону и компьютеру. Компоненты выносятся в единый набор; загрузка, ошибка, пустое состояние и работа с клавиатурой проектируются вместе с основным экраном.

## Порядок реализации

1. Зафиксировать сценарии текущего кабинета и контракты JSON API. Учесть вход/выход, CSRF, ошибки валидации и отказ в доступе; TypeScript на клиенте не заменяет серверную проверку.
2. Создать React/TypeScript/Vite приложение, маршруты, общий каркас и компоненты кнопок, полей, списков, чекбоксов, таблиц и уведомлений.
3. Перенести вход, проекты, приложения и управление ключами. Пароли БД, ключи чтения и другие серверные секреты не включать в клиентскую сборку. Сеанс хранить в защищённой HttpOnly cookie.
4. Перенести экран подключения и оболочку Grafana. Сохранить изоляцию владельцев, проверку прав в шлюзе Grafana и одинаковые периоды/темы при открытии полной панели.
5. Подготовить отдельный контейнер frontend, который раздаёт собранные статические файлы. API и защищённая Grafana проходят через общий внешний адрес; CORS и доверенные заголовки настраиваются явно. Отдельный контейнер Express продолжает обслуживать API. Общий Compose должен подниматься без ручной настройки; образы собираются для linux/amd64 и linux/arm64.
6. Проверить полную цепочку и только затем переключить основной кабинет. EJS кабинета удаляется после проверки замены; исторические ветки и версии лабораторных сохраняются.

## Критерии готовности

- Два владельца видят только свои проекты, приложения и события; подмена ID не открывает чужие данные.
- Вход, выход, ошибки формы, истёкший сеанс, замена/отзыв ключа и архивирование работают через новый интерфейс.
- Android и Web SDK доставляют прежние пакеты с ACK и без удвоения событий.
- В Grafana совпадают счётчики, быстрые и календарные периоды, сравнение равных интервалов и анализ переходов между экранами; приватную панель нельзя открыть в обход прав владельца.
- Светлая/тёмная темы и размеры 390/1280 px проверены, работают клавиатура и прямое открытие URL разделов.
- В рабочей сборке отсутствуют dev-сервер и серверные секреты; пересоздание контейнеров сохраняет данные. Подтверждены запуск на Intel и наличие ARM64 в том же теге.

## Что известно о MyTracker

В официальном документе MyTracker «Функциональные характеристики программного обеспечения», Москва, 2024, на странице 6 клиентское приложение описано как написанное на JavaScript, сервер веб-кабинета — на PHP. Конкретный JavaScript-фреймворк не назван. Это историческое описание, а не доказательство текущего стека; считать использование React подтверждённым нельзя. Выбор React для нашего проекта основан на сценариях будущего кабинета.

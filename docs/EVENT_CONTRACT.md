# Контракт событий v1

Реализован в сервере 0.1.0. Дата: 04.10.2026. Приложение отправляет постоянные имена событий и ограниченный набор свойств; сервер назначает проект по ключу и сохраняет время получения отдельно.

## Приём пакета

`POST /api/v1/events`. Заголовки: `Authorization: Bearer <ingestKey>`, `Content-Type: application/json`. Ключ передаётся целиком. В JSON нет ключа доступа или `projectId`.

```json
{
  "schemaVersion": 1,
  "events": [{
    "eventId": "5b2f5a32-a6c2-46b3-9735-e5b605eb89a1",
    "sessionId": "aab3806c-33e1-4b58-bc81-f5d8b01a5bd0",
    "occurredAt": "2026-10-04T10:20:30.000Z",
    "name": "button_click",
    "screen": "collection",
    "platform": "android",
    "appVersion": "1.0.0",
    "properties": { "button": "add_model" }
  }]
}
```

При отправке используйте реальное время действия. Пакет: **1–100 событий**, HTTP-тело до **64 КиБ**. Неизвестные поля отклоняются; расширения требуют изменения контракта.

| Поле | Правило | Назначение |
|---|---|---|
| `schemaVersion` | Число `1`, на уровне пакета | Версия формата |
| `eventId` | UUID, обязательный | Постоянный ID события, сохраняется при повторах |
| `sessionId` | UUID, обязательный | Сессия клиента |
| `occurredAt` | UTC ISO 8601, секунды или 3 цифры миллисекунд, `Z` | Время действия, независимо от отправки |
| `name` | `[a-z][a-z0-9_]{0,63}` | `screen_view`, `button_click`, `action_success` |
| `screen` | Та же форма имени; можно пропустить/передать `null` | Например, `collection` |
| `platform` | `android`, `ios`, `web` | Платформа клиента |
| `appVersion` | Строка 1–32 символа | Версия приложения |
| `properties` | Плоский объект; можно пропустить/передать `null` | Контекст действия |

UUID нормализуются к нижнему регистру. Дата проверяется по календарю: не старше 365 суток и не более 5 минут в будущем относительно сервера. Смещение часового пояса преобразуется в UTC до отправки.

Свойства: до **16** ключей в формате имени события; значения — строка до **256** символов, конечное число, boolean или null. Вложенные объекты/массивы не принимаются; размер JSON свойств до **4 КиБ**. Имена `__proto__`, `constructor`, `prototype` запрещены. Порядок свойств не влияет на определение повтора.

## Подтверждение и повторы

HTTP 200 **после COMMIT в DuckDB**:

```json
{
  "schemaVersion": 1,
  "accepted": 1,
  "duplicates": 0,
  "acknowledgedEventIds": ["5b2f5a32-a6c2-46b3-9735-e5b605eb89a1"]
}
```

`accepted` — новые записи; `duplicates` — уже сохранённые события и одинаковые повторы внутри пакета. Подтверждения содержат уникальные ID; SDK удаляет из очереди только подтверждённые события.

При потере ответа повторяется тот же ID, время, сессия и содержимое. Второго учёта нет. При изменённом содержимом с тем же ID — 409, **весь пакет отклонён**. Новый ID при каждом повторе нарушает доставку без двойного учёта.

Ошибка одного события отклоняет весь пакет: частичной записи нет. Уникальна пара `(project_id, event_id)`; ID разных проектов независимы. Сейчас HTTP API обслуживает один проект из конфигурации; управление несколькими проектами пока не реализовано.

## Ошибки

```json
{
  "error": {
    "code": "invalid_event",
    "message": "Требуется UUID.",
    "field": "events[0].eventId"
  }
}
```

| HTTP | Код | Действие клиента |
|---|---|---|
| 400 | `invalid_event`, `invalid_json` | Исправить формат; не повторять бесконечно ошибочный пакет |
| 401 | `unauthorized` | Проверить ключ, остановить отправку до исправления |
| 409 | `event_id_conflict` | Диагностика постоянства ID; не создавать новый ID для обхода |
| 413 | `payload_too_large` | Разделить пакет по размеру |
| 415 | `unsupported_media_type` | Передать `application/json` |
| 503 | `server_busy` | Задержка и повтор; `Retry-After: 1` |
| 500 | `internal_error` | Ограниченный повтор с задержкой и тем же содержимым |

Сервер пока не выставляет 429 самостоятельно: отдельное ограничение частоты добавим перед публичным размещением. Будущая SDK учитывает 429 и `Retry-After` API/прокси. Отказ HTTP не является подтверждением записи.

## Статистика

`GET /api/v1/stats?days=7`, `Authorization: Bearer <readKey>`. `days`: целое 1–90, по умолчанию 7. `ingestKey` не позволяет смотреть данные. Ответ: проект, UTC-границы периода, `totals.events`, `totals.sessions`, `daily`, `byName`, `byScreen`.

- Период включает текущий UTC-день, `from` включительно, `until` — начало следующего дня, исключительно.
- Фильтр по `occurredAt`: поздно доставленное событие относится к дню действия.
- `received_at` — время получения сервером, хранится в БД отдельно.
- Дни без событий возвращаются с нулём.
- Сессии — разные `sessionId` с событиями в периоде, не пользователи.
- `byScreen` считает **все события** с экраном, не только открытия.
- `byName` и `byScreen`: до 100 групп каждой таблицы. Общие/дневные суммы включают все группы.

`GET /health` без ключа показывает статус запущенного сервера и версию; это не нагрузочная проверка.

## Границы сбора

Фотографии, коллекции, введённые тексты, рекламные ID и автоматический захват всех касаний не предусматриваются. Разработчик явно отмечает действия. Свойства — постоянные имена кнопок/фильтров/результатов; не передавайте туда личные данные и пользовательский ввод. Ключ просмотра не встраивается в мобильное приложение.

# Второй ПК: запуск и ручные проверки

## Что установить

1. GitHub Desktop или Git для получения исходников.
2. Docker с поддержкой Linux-контейнеров. На Windows 11 виртуальной машины используйте уже работающий Docker Desktop и его текущий механизм виртуализации.
3. Браузер для `http://localhost:8080`.

Для ЛР1 не требуется отдельно ставить Node.js, npm, Express, DuckDB, Android Studio или получать сторонние ключи. Docker загрузит базовый образ и пакеты во время сборки на втором ПК.

## Подготовка исходников

Локальный репозиторий уже создан в `D:\MyTracer SDK CopyStyle`, ветка `main`, коммитов пока нет. На первом ПК в GitHub Desktop выберите **File → Add local repository → Choose**, укажите эту папку и нажмите **Add repository**. Создавать дополнительную вложенную папку не требуется: `Dockerfile` и `package.json` уже лежат в корне репозитория.

Проверьте файлы и сделайте свой первый коммит, например `Initial Setup: add analytics service lab 1`. Затем нажмите **Publish repository**, задайте имя `UlsaTracerStyle-SDK` и уберите **Keep this code private**, если публикуете исходники открыто для преподавателя. Файл `.gitignore` уже подготовлен; шаблон C++ не нужен. После публикации клонируйте репозиторий на втором ПК и откройте терминал в его корне. На следующих этапах повторяйте Fetch/Pull перед сборкой.

## Команды

```bash
docker version
docker build -t ulsatracerstyle-sdk:0.0.1 .
docker run --rm -p 8080:8080 --name ulsa-tracer-lab1 ulsatracerstyle-sdk:0.0.1
```

Последняя команда работает до остановки контейнера. В браузере откройте [http://localhost:8080](http://localhost:8080). Логи видны в терминале. В другом терминале:

```bash
docker logs ulsa-tracer-lab1
docker stop ulsa-tracer-lab1
```

При занятом порте сначала остановите предыдущий контейнер. Загрузка образа в реестр описана в `README.md`; используйте новый образ UlsaTracerStyle SDK, а не прежний образ сервиса импорта.

## ЛР1 — выполнить сейчас на втором ПК

- [ ] A01. Docker собрал образ из корня нового репозитория без ошибок.
- [ ] A02. После `docker run` страница доступна по `http://localhost:8080`.
- [ ] A03. Видны название UlsaTracerStyle SDK, описание сервиса аналитики, версия 0.0.1 и «Разработка продолжается».
- [ ] A04. На узком окне 320–360 px текст помещается, горизонтальной прокрутки нет; широкое окно тоже читаемо.
- [ ] A05. При светлой/тёмной системной теме текст и фон читаемы.
- [ ] A06. `docker stop` завершает контейнер, повторный `docker run` снова открывает страницу.
- [ ] A07. Новый образ опубликован публично; `docker pull` и `docker run` из README работают на другом Docker-хосте без входа в реестр. Во время проверки нужен доступ к интернету.
- [ ] A08. Скриншот сделан именно новой страницы; фактические GitHub/Docker Hub ссылки записаны для отчёта.
- [ ] A09. Если опубликованы amd64 и arm64: обе платформы проверены на соответствующих машинах или согласованной эмуляции; в отчёте указано, что реально проверено.

- [ ] B03. Без интернета приложение работает; после восстановления связи очередь доставляется согласно политике SDK.

# Docker: запуск на ноутбуке или втором ПК и ручные проверки

## Что установить

1. GitHub Desktop или Git для получения исходников.
2. Docker с поддержкой Linux-контейнеров. Для ноутбука — [инструкция Docker Desktop](DOCKER_SETUP.md). На втором ПК используйте уже работающий Docker Desktop.
3. Браузер для `http://localhost:8080`.

Для ЛР1 не требуется отдельно ставить Node.js, npm, Express, DuckDB, Android Studio или получать сторонние ключи. Docker загрузит базовый образ и пакеты во время сборки на выбранном ПК.

## Подготовка исходников

Пользователь уже сделал первый коммит и пуш и переименовал репозиторий в [Semiys/UlsaTrackerStyle-SDK](https://github.com/Semiys/UlsaTrackerStyle-SDK). Локальная папка ноутбука — `D:\MyTracer SDK CopyStyle`, ветка `main`; `origin` использует новый адрес. На втором ПК клонируйте репозиторий и откройте терминал в его корне. При проверке со второго ПК повторяйте Fetch/Pull после новых коммитов пользователя. Если клон создан до переименования, обновите адрес командой `git remote set-url origin https://github.com/Semiys/UlsaTrackerStyle-SDK.git` в папке того клона.

## Команды

```bash
docker version
docker build -t ulsatrackerstyle-sdk:0.0.1 .
docker run --rm -d -p 127.0.0.1:8080-8180:8080 --name ulsa-tracker-auto ulsatrackerstyle-sdk:0.0.1
docker port ulsa-tracker-auto 8080/tcp
```

Контейнер работает в фоне; последняя команда показывает выбранный адрес. Откройте его с префиксом `http://`, например `http://127.0.0.1:8082`. Просмотр логов и остановка:

```bash
docker logs -f ulsa-tracker-auto
docker stop ulsa-tracker-auto
```

При занятости портов другими контейнерами Docker выберет свободный из диапазона 8080–8180. Для повторного запуска с тем же именем сначала остановите свой экземпляр. Если занят весь диапазон или порт заблокирован обычной программой Windows, задайте другой диапазон. Загрузка образа в реестр описана в `README.md`; используйте образ UlsaTrackerStyle SDK.

## Публикация и проверка двух архитектур

После локальной проверки выполните Buildx-сборку и публикацию из README. Проверьте манифест:

```bash
docker buildx imagetools inspect semiys/ulsatrackerstyle-sdk:0.0.1
```

Должны присутствовать `linux/amd64` и `linux/arm64`. Затем по очереди запустите опубликованные варианты. Между запусками остановите предыдущий контейнер через `Ctrl+C` или `docker stop`:

```bash
docker pull --platform linux/amd64 semiys/ulsatrackerstyle-sdk:0.0.1
docker run --rm --platform linux/amd64 -p 8080:8080 --name ulsa-check-amd64 semiys/ulsatrackerstyle-sdk:0.0.1
```

```bash
docker pull --platform linux/arm64 semiys/ulsatrackerstyle-sdk:0.0.1
docker run --rm --platform linux/arm64 -p 8080:8080 --name ulsa-check-arm64 semiys/ulsatrackerstyle-sdk:0.0.1
```

В каждом запуске отдельно откройте `http://localhost:8080`, проверьте страницу и логи. На Intel-ноутбуке ARM64 запускается через эмуляцию; зафиксируйте это в отчёте. По возможности повторите ARM64 на настоящем ARM-хосте. Наличие платформ в манифесте подтверждает публикацию, но не заменяет проверку запуска.

## Публикация и автоматический выбор порта 04.10.2026

Пользователь опубликовал `semiys/ulsatrackerstyle-sdk:0.0.1`. Агент повторно прочитал индекс: обе платформы присутствуют; `unknown/unknown` — манифесты аттестаций. Digest индекса — `sha256:e2c58257bbffeea835d8889447d2f97aa3587cf687d4eb3da18bca39e04644e6`. `docker manifest inspect` и `docker pull` с отдельной пустой конфигурацией выполнены без авторизации успешно. Оба опубликованных варианта затем запущены одновременно: AMD64 получил `127.0.0.1:8082`, ARM64 — `127.0.0.1:8083`; главная страница и CSS на каждой платформе ответили HTTP 200, заголовок UlsaTrackerStyle SDK присутствует. ARM64 проверен через эмуляцию на Intel.

Автовыбор — стандартная публикация одного контейнерного порта в диапазон портов компьютера. Другие контейнеры не останавливаются. На ноутбуке проверено: занятые другими контейнерами 8080 и 8081 пропущены, новый экземпляр получил 8082; при полностью занятом диапазоне 8080–8081 получена явная ошибка. Найдено ограничение Docker Desktop: Windows TCP-программа на первом порте диапазона вызывает ошибку `ports are not available`, поэтому для такого случая в инструкции предусмотрена смена диапазона. Временные проверочные контейнеры удалены; два исходных контейнера пользователя сохранены.

## ЛР1 — ручные проверки пользователя

- [ ] A01. Docker собрал образ из корня нового репозитория без ошибок.
- [ ] A02. После `docker run` и `docker port` страница доступна по показанному адресу.
- [ ] A03. Видны название UlsaTrackerStyle SDK, описание сервиса аналитики, версия 0.0.1 и «Разработка продолжается».
- [ ] A04. На узком окне 320–360 px текст помещается, горизонтальной прокрутки нет; широкое окно тоже читаемо.
- [ ] A05. При светлой/тёмной системной теме текст и фон читаемы.
- [ ] A06. `docker stop` завершает контейнер, повторный `docker run` снова открывает страницу.
- [ ] A07. Новый образ опубликован публично; `docker pull` и `docker run` из README работают на другом Docker-хосте без входа в реестр. Во время проверки нужен доступ к интернету.
- [ ] A08. Скриншот сделан именно новой страницы; фактические GitHub/Docker Hub ссылки записаны для отчёта.
- [ ] A09. Обязательная публикация двух платформ: в манифесте есть `linux/amd64` и `linux/arm64`; обе запускаются и показывают страницу. Для каждой записано, использовался настоящий хост или эмуляция.
- [ ] A10. При занятых другими контейнерами 8080 и 8081 новый контейнер выбирает свободный порт из диапазона 8080–8180; страница открывается по адресу из `docker port`, прежние контейнеры продолжают работать.
- [ ] A11. Два экземпляра с разными именами получают разные порты. После остановки одного второй продолжает отвечать.
- [ ] A12. При полностью занятом диапазоне получается явная ошибка; ни один прежний контейнер не остановлен. С другим свободным диапазоном запуск успешен.

# Удаление отдельного приложения — 0.11.2

Дата: 05.11.2026. Текущий Android package name «Дома Коллекционера»: `ru.semius.domcollection`. Изменение идентификатора APK само по себе не переключает SDK на другой ключ: перед удалением прежнего приложения нужно убедиться, что SDK использует ключ нового приложения в кабинете.

## Как удалить

1. Открыть проект и выбрать приложение со старым идентификатором.
2. Внизу его страницы открыть «Удалить приложение».
3. Проверить название и идентификатор в подтверждении. Будут удалены выбранное приложение, все его ключи, панель Grafana и накопленные события. Проект и другие приложения сохраняются.
4. Ввести именно идентификатор удаляемого приложения. Значение другого приложения не включает кнопку подтверждения. Нажать «Удалить без возможности восстановления».
5. После успеха открывается прежний проект с оставшимися приложениями. Старые ключи больше не принимают события. Повторное создание приложения даёт новый ID и новый ключ, без прежней статистики.

Если удаление прервалось, карточка остаётся с действием «Завершить удаление», ключи выключены, создание тестовых событий и просмотр прежних данных закрыты. Повторить удаление можно на той же странице. Отмена до отправки запроса ничего не меняет. После начала серверной операции отмены и восстановления через кабинет нет.

## Реализация

POST /api/console/apps/:appId/delete принимает confirmation с точным идентификатором и обычный csrfToken. Проверяются сеанс, владелец и общий лимит изменений. Несовпадение подтверждения возвращает 400 до любых изменений; чужой ID — 404.

SQLite хранит отметку незавершённого удаления. Все ключи выбранного приложения отзываются одной транзакцией. Приложение исключается из списка разрешённых ClickHouse-проектов владельца; удаляется его панель Grafana. События удаляются параметризованным запросом только по внутреннему ID приложения. ClickHouse ожидает завершения мутации; операции проходят через существующую очередь записи. После очистки удаляются метаданные приложения и его ключей. При сбое метаданные сохраняются для повторной попытки, приём не включается обратно.

Приложение повторно проверяет ключ после получения тела SDK-запроса: старый медленный запрос не может дописать данные после удаления/отзыва. JSON-хранилище сохраняет очистку атомарно; сохранён адаптер удаления для DuckDB. Для текущего выпуска полная интеграция проверена с ClickHouse.

Grafana 13 кешировала набор разрешённых панелей после первого открытия; немедленное открытие второго приложения давало 403 до обновления кеша. В продуктовой Grafana отключён только кеш RBAC (`GF_RBAC_PERMISSION_CACHE=false`). Проверки Viewer, разделение организаций, шлюз и SQL row policies сохранены. Поведение проверено с двумя владельцами и двумя приложениями. [Описание параметра Grafana](https://grafana.com/docs/grafana/latest/administration/roles-and-permissions/access-control/configure-rbac/).

## Миграция и проверка

Схема метаданных аккаунтов автоматически переводится с версии 1 на 2 добавлением nullable-поля applications.deleting_at. Аккаунты, сеансы, проекты, идентификаторы и ключи при этом сохраняются. Возврат к бинарной версии 0.11.1 требует восстановления согласованной копии appdata до миграции; старый код не поддерживает схему 2.

Полный прогон на Intel/amd64: **129/129**, ошибок и пропусков нет. TypeScript и production-сборка Vite успешны. Отдельно проверены миграция заполненной схемы 1, сохранность второго приложения, чужой владелец/CSRF/неверное подтверждение, параллельные запросы, сбой после уже выполненной очистки, повтор и медленное тело запроса.

Через настоящий frontend-шлюз проверены отзыв старого ключа, очистка панели и сохранение панели/событий соседнего приложения. Отдельный запрос к ClickHouse подтвердил отсутствие физических строк выбранного ID после завершения мутации и сохранность соседних строк. В браузере проверены правильный и неправильный идентификаторы, отмена и ширина 390 px (содержимое 375 px без горизонтального переполнения). Ручное удаление реальных приложений в эти проверки не входит. Физический телефон и ARM64 этим изменением повторно не проверялись.

## Что проверить пользователю

- Обновить страницу основного кабинета и проверить версию 0.11.2 в подвале.
- Убедиться, что новое приложение имеет идентификатор ru.semius.domcollection, а APK использует его ключ.
- На старом приложении открыть подтверждение, нажать «Отменить» и убедиться, что оба приложения остались.
- Повторно открыть подтверждение и удалить старое приложение, только если его история больше не нужна.
- Проверить, что новый ключ принимает событие и графики нового приложения доступны.

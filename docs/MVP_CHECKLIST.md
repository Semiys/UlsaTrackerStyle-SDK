# Проверки первого серверного блока 0.1.0

История проверок блока 0.1.0 от 04.10.2026: API, DuckDB и веб-статистика до мобильной SDK. В 0.2.0 появилась Android/JVM SDK; её отдельные проверки — [SDK_CHECKLIST.md](SDK_CHECKLIST.md). Здесь сохранены результаты прежнего блока.

## Подготовка

Запуск — в [README](../README.md): `ulsa-tracker-dev`, том `ulsa-tracker-dev-data`. Узнайте порт через `docker port`, ключи — через `docker exec ulsa-tracker-dev node src/show-access.js`. Откройте `/dashboard`.

Ранее записанные события остаются. Для пустого проекта используйте новое имя тома, например `ulsa-tracker-manual-data`, и отдельное имя контейнера; не удаляйте рабочий том.

## Ручные проверки

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Открыть `/`, `/health` | Правильное название, версия 0.1.0, health `ok` |
| 2 | `/dashboard` без ключа | Форма доступа, статистика скрыта |
| 3 | Неверный ключ | Понятная ошибка; форма доступна |
| 4 | `ingestKey` вместо `readKey` | Просмотр отклонён |
| 5 | `readKey` на новом томе | «Дом Коллекционера», 0 событий/сессий, пустые таблицы/график |
| 6 | `docker exec ulsa-tracker-dev node src/send-test-event.js --new` | HTTP 200, `accepted: 1`, `duplicates: 0` |
| 7 | «Обновить» | +1 событие, `button_click`, экран `sdk_check`, столбец сегодняшнего UTC-дня |
| 8 | `docker exec ulsa-tracker-dev node src/send-test-event.js --repeat`; «Обновить» | `accepted: 0`, `duplicates: 1`; счётчик не вырос |
| 9 | Снова `--new` | +1 событие и новая тестовая сессия |
| 10 | Период 7 ↔ 30 дней | Нужное число дней; сегодняшние события присутствуют в обоих периодах |
| 11 | «Закрыть доступ» | Форма, пустое поле, статистика скрыта |
| 12 | Открыть с ключом, обновить страницу браузера | Нужен повторный ввод; ключ не записан в localStorage/sessionStorage |
| 13 | Остановить, запустить с тем же томом | Ключи/события сохранены; `--repeat` не увеличивает счётчик |
| 14 | `/data/access.json` | HTTP 404, файл ключей не выдан |
| 15 | Узкое окно телефона и широкий экран ПК | Карточки перестраиваются; график прокручивается внутри блока |
| 16 | Светлая/тёмная системные темы | Контрастные поля, кнопки, текст и график |

Даты считаются в UTC. Сессии — не пользователи; «Экраны» показывает все события с экраном.

## Автоматический прогон

```bash
docker build --target test -t ulsa-tracker-tests:0.1.0 .
docker run --rm --memory 512m --cpus 2 ulsa-tracker-tests:0.1.0
```

Проверки: разные права ключей и закрытые файлы; подтверждение записи; одинаковые/конфликтующие ID; атомарное отклонение; параллельные повторы; ограничения JSON/полей; даты; UTC-период; закрытие/повторное открытие DuckDB; изоляция проектов/параметры SQL; переполнение очереди; отказ от несовместимой схемы без её изменения; диагностическая команда. Рабочий том не используется.

## Результаты

- Итоговые **14/14 автоматических проверок прошли на AMD64 и ARM64**. AMD64 — Intel-ноутбук; ARM64 — эмуляция Docker Desktop. Проверяются настоящая DuckDB и HTTP.
- Runtime 0.1.0 обеих архитектур: HTTP 200 главной страницы, dashboard, JS/CSS и health; пустая база; ручное событие и повтор. После остановки и пересоздания контейнера с тем же томом сохранились ключи, событие и защита от двойного учёта.
- Образ запускается от пользователя `node`, не root. В runtime отсутствуют `test`, `docs`, `.git`.
- В браузере проверены неверный ключ, успешный просмотр, период 7/30 дней, реальные таблицы/график, закрытие доступа и обновление страницы. Компоновка проверена при ширине 390 и 1280 пикселей; горизонтального переполнения страницы нет, широкий график прокручивается внутри блока. Проверена тёмная тема; светлую тему и реальный телефон пользователь проверяет отдельно.
- Для ручных проверок оставлен `ulsa-tracker-dev` с новым пустым томом `ulsa-tracker-dev-data` на `http://127.0.0.1:8080/dashboard`, лимитами 512 МБ и 2 CPU. Диагностические события проверки удалены вместе с отдельными временными томами; рабочая база пустая.
- Android/KMP, сеть телефона, физический ARM-компьютер ещё не проверены.
- 0.1.0 — локальная сборка; GitHub и Docker Hub автоматически не обновлялись.

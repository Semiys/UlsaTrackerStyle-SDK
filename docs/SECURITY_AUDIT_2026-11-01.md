# Аудит безопасности и мониторинг — 1 ноября 2026

Объект: локальная серверная версия **0.10.0**, кабинет, шлюз Grafana, ClickHouse и новый мониторинг. Исходная ветка — выпуск 0.9.0; результаты относятся к изменениям текущей ветки. Публикация и слияние не выполнялись. Отчёты лабораторных работ и опубликованные образы 0.0.1–0.0.4/0.9.0 не изменены.

Проверены исходники границ доступа, HTTP-контракт, зависимости npm, состав контейнеров, сессии/CSRF, межклиентская изоляция, права SQL, ограничения запросов, доступ к метрикам и обнаружение отказов. Испытания выполнялись на отдельных аккаунтах и томах `ulsa-security-audit`. Это инженерный аудит указанных границ, а не сертификация, внешнее тестирование публичной сети или доказательство отсутствия любых уязвимостей. Телефон и мобильные SDK в этом прогоне заново не тестировались.

## Исправленные проблемы

| Наблюдение | Исправление и проверка |
|---|---|
| Выключение деморежима могло сохранить известные публичные ключи из старого `access.json` | Запуск с DEMO_MODE=0 и такими реквизитами теперь прекращается. Отдельный тест на сохранённом конфиге. Нужна явная миграция или новый закрытый том; секреты не переименовываются автоматически. |
| Шлюз заменял CSP Grafana и терял ограничения выполнения скриптов | Сохраняются upstream CSP и nonce, меняется только frame-ancestors для кабинета. Проверены поддельные Cookie/Authorization/orgId, чужой redirect и административный POST. |
| Известные уязвимости зависимостей и устаревшие компоненты запуска | Обновлён lockfile (body-parser/qs), Node 24.22.2 и системные пакеты, Grafana 13.3.0, ClickHouse 26.8.34.13 LTS, ClickHouse-плагин 4.23.4. Компоненты меняются только в новом варианте запуска. |
| Неиспользуемые backend-плагины Grafana содержали критические CVE | В новой локальной сборке оставлены ядро, необходимый подписанный Prometheus-плагин и отдельный ClickHouse-плагин. Скан итоговой Grafana не находит High/Critical; остаточные находки ниже. |
| Запрос клиента через Grafana должен ограничиваться также по ресурсам БД | Профиль читателя: readonly, 2 потока, 256 МиБ на запрос, максимум 60 секунд, 10 000 строк / 8 МиБ результата. Повышать ограничения нельзя; max_execution_time разрешён в пределах профиля для совместимости плагина. |
| Обновление Grafana ввело новый namespaced API, который прежний шлюз блокировал | Разрешены только необходимые чтения и оценка feature flags; namespace жёстко связан с организацией текущего владельца. Проверены своя/чужая панель, чужой namespace и запрет DELETE/PUT. Итоговая панель дополнительно открыта в браузере. |
| Техническая статистика не должна стать доступна клиентам | Отдельный внутренний listener метрик и отдельная Grafana оператора. Нет Docker socket, анонимного входа в операторскую панель и Prometheus-datasource в клиентских организациях. |
| Новые служебные пароли не должны быть общими или попадать в Git | Случайные разные файлы Docker secrets, отдельная служебная группа, без world-readable разрешений. Git ignore и исключение из app build context проверены. |

Существующие меры сохранены: scrypt с солью, случайные серверные сессии (в БД хеш токена), HttpOnly/SameSite-cookie, CSRF, ограниченные тела запросов, EJS-экранирование, параметризованные запросы данных, отзыв ключей, ограничители попыток и пакетов. Они не заменяют недостающий жизненный цикл аккаунта.

## Изоляция владельцев

Через реальный `/grafana/api/ds/query` владелец A выполнил SQL **без WHERE**: вернулись только его строки. Подмена orgId и Authorization не изменила владельца. Доступ к appId, CSV и панели B вернул 404. Получить источник `ulsa-monitoring` из клиентского кабинета не удалось.

`DROP TABLE`, `url()` с внутренним адресом, `remote()` с известными демонстрационными реквизитами и чтение `app.schema_version` отклонены именно из-за прав/readonly, а не синтаксической ошибки. Проверки требуют соответствующую причину отказа. Политика строк работает в ClickHouse, а не только в фильтре нарисованной панели. Данные разных приложений одного владельца по текущей модели доступны этому владельцу; отдельных ролей сотрудников пока нет.

Дополнительно проверены поддельная сессия, POST без CSRF/с чужим токеном, сохранённый HTML в названии проекта, приватное no-store-кэширование и выход из кабинета. Старые проверки покрывают разграничение ключей чтения/приёма, отзыв ключа, CORS, дубликаты, некорректные пакеты и CSV-инъекции.

## Зависимости и остаточные CVE

`npm audit --omit=dev --omit=optional` в итоговом образе: **0 известных уязвимостей**; до исправления lockfile были 1 High и 1 Moderate. Это результат npm advisory database на момент проверки, не всех библиотек внутри образа.

Docker Scout 1.24.0, локальные linux/amd64-образы. Ниже уникальные идентификаторы CVE/advisory внутри каждого образа; один CVE в нескольких пакетах считается один раз. Между образами значения не суммируются. Уровень определён по security-severity SARIF.

| Итоговый компонент | Всего | Critical | High | Medium | Low |
|---|---:|---:|---:|---:|---:|
| Сервер 0.10.0, Node 24.22.2 и плагин 4.23.4 | 72 | 0 | 14 | 16 | 42 |
| Grafana 13.3.0-slim + необходимый Prometheus-плагин | 6 | 0 | 0 | 1 | 5 |
| ClickHouse 26.8.34.13 | 31 | 0 | 4 | 23 | 4 |
| Prometheus 3.13.5 LTS | 9 | 0 | 2 | 3 | 4 |

Промежуточная app-сборка с Node 24.21.0 и старым ClickHouse-плагином имела 191 уникальную находку; обновления сократили их до 72. Стандартный Grafana 13.3.0 содержал 22 находки, в том числе CVE-2026-78663 и CVE-2026-56857 в лишних backend-плагинах; этих бинарников нет в итоговом образе. Точное влияние оставшихся находок на используемые пути исполнения не доказано. Их нельзя объявить безопасными только потому, что сервис работает локально; требуется контроль обновлений поставщиков и отдельная проверка достижимости перед публичным выпуском.

История Git дополнительно проверена поиском характерных форматов приватных ключей и API-токенов: 394 текстовых blob, совпадений не найдено. Это ограниченный поиск по шаблонам, а не гарантия отсутствия произвольного секрета. Демонстрационные app/app и публичные lab-ключи известны и не считаются закрытыми паролями.

## Воспроизводимость и результат проверок

- **101/101 тест**, 0 ошибок и 0 пропусков, после обновления Grafana/плагина и ClickHouse.
- promtool: конфигурация и четыре правила корректны; Prometheus собирает API, ClickHouse и себя.
- Остановка только тестового API: up=0, UlsaApiDown перешла pending → firing; после запуска тревога снялась.
- Остановка только тестовой БД: up{job=clickhouse}=0, ulsa_storage_available=0, UlsaStorageUnavailable перешла в firing; после запуска показатели и состояние восстановились.
- Операторская Grafana требует входа; продуктовый `/metrics` возвращает 404, внутренние 9100/9363 не опубликованы.
- Отдельные метрики не содержат appId, email, токенов и содержимого коллекции; шаблоны маршрутов проверены на множестве разных URL.

Локальная сборка сервера ARM64 и шесть тестов безопасности/метрик под эмуляцией успешны; полноценный интеграционный прогон выполнен на amd64. Manifest официальных образов ClickHouse, Grafana и Prometheus содержит amd64 и arm64. Работа на физическом ARM-устройстве в этом аудите не проверялась.

Перед обновлением основного стенда проверены gzip-архивы остановленных томов appdata/dbdata. После обновления число событий FINAL совпало; старые тома Grafana сохранены. Все пять сервисов основного стенда healthy.

Команды повторения и устройство мониторинга: [MONITORING.md](MONITORING.md). Сырые журналы, SARIF и результаты остановок хранятся локально вне репозитория; они не включаются в публичный Docker-образ. Автоматические проверки нельзя запускать на пользовательских томах.

## Что остаётся до публичного SaaS

1. **HTTPS и секреты.** Локальный Compose сохраняет HTTP и демонстрационные реквизиты ClickHouse для прежнего стенда. Нужны TLS, корректный PUBLIC_URL/Secure-cookie, выключенное публичное демо и согласованная ротация уже сохранённых секретов. Fail-closed проверка демоключей сама по себе не выполняет миграцию.
2. **Привилегии сервера.** API ещё создаёт схему, пользователей и row policies. Вынести миграции/подготовку изоляции и отделить полномочия записи от администрирования БД. Изоляция клиентов проверена, но компрометация самого API остаётся серьёзным риском.
3. **Оставшиеся CVE.** Контроль обновлений и анализ применимости. Отсутствие Critical в текущем скане не является допуском к публикации.
4. **Защита от злоупотреблений.** Ключ внутри клиентского приложения извлекаем. Он разрешает запись в своё приложение, но не доказывает подлинность каждого события. Нужны общие квоты, лимиты регистрации/хранения и защита внешнего входа. Текущие ограничители находятся в памяти одного процесса.
5. **Аккаунты и кластер.** SQLite кабинета и одноэкземплярные лимиты не готовы к нескольким независимым API. Подтверждение почты, восстановление доступа, MFA, отзыв всех сессий, роли и журнал безопасности **оставлены в плане**, а не реализованы в этом изменении. Параметры scrypt (сейчас N=16384, r=8, p=1) отдельно пересмотреть с учётом бюджета памяти и актуальных рекомендаций. При регистрации ответ 409 также позволяет отличить уже зарегистрированный email; устранение перечисления аккаунтов включить в этот этап.
6. **Эксплуатация.** Проверить восстановление резервных копий и ротацию, добавить Alertmanager/уведомления, определить срок хранения продуктовых событий и порядок удаления. Retention Prometheus касается только технических метрик.

Общий вывод: проверенные границы между клиентами работают, несколько конкретных слабых мест исправлены, технический мониторинг реализован. Готовность к публичному размещению и соответствие ГОСТ не заявляются.

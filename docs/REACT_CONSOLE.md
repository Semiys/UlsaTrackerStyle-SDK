# React-интерфейс 0.12.0

Кабинет перенесён на React 19.3.1, TypeScript 7.0.2, Vite 8.3.5 и React Router 7.18.5. Точные зависимости закреплены в frontend/package-lock.json. Демонстрационный выпуск опубликован как 0.0.5: [быстрый запуск](../README.md#запуск). Ниже — отдельная локальная сборка с операторским мониторингом, она не разворачивается автоматически.

## Что перенесено

Главная, регистрация, вход и выход, проекты и их архив, приложения, одноразовая выдача/замена/отзыв ключей, инструкция подключения, тестовое событие и оболочка Grafana. Сохраняются адреса разделов, обе темы, оформленные списки/чекбоксы, календарь, весь период, местное время, CSV и JSON.

Публичные страницы /dashboard, /events/new, /error, /sdk-demo и новый /system-state также перенесены на React. Прежние серверные шаблоны сохранены для совместимости и регрессионных проверок; обычный пользовательский интерфейс их не использует.

Кнопка «Демонстрация» в шапке видна только гостю при включённом деморежиме. После входа она скрывается; при выходе снова доступна гостю.

## Запуск

Нужен Docker Desktop с Linux-контейнерами или Docker Engine + Compose с поддержкой !override. Не требуется устанавливать Node/npm на компьютер.

Из корня репозитория, при первом запуске создайте локальные секреты:

```powershell
docker run --rm --user 0 --mount "type=bind,source=$($PWD.Path),target=/workspace" -w /workspace node:24.22.2-bookworm-slim node scripts/init-monitoring.mjs
```

Скрипт сохраняет существующие секреты. Затем:

```bash
docker compose -f docker-compose.yml -f docker-compose.monitoring.yml -f docker-compose.react.yml up -d --build --wait
```

Кабинет: http://localhost:8080. Prometheus: http://localhost:9091. Панель оператора: http://localhost:3100. Должны быть свободны эти три порта. Для входа оператора используйте инструкцию MONITORING.md; секреты не передавайте в чат и не добавляйте в Git.

В React-конфигурации внешний порт 3000 убран: браузер, API и защищённая Grafana работают через frontend на одном адресе. API, ClickHouse и продуктовая Grafana напрямую не публикуются. Vite используется только при сборке; рабочего dev-сервера нет.

Остановка с сохранением данных:

```bash
docker compose -f docker-compose.yml -f docker-compose.monitoring.yml -f docker-compose.react.yml down
```

Не добавляйте -v: данные находятся в постоянных томах.

## Проверка с телефона по Wi-Fi

По умолчанию frontend доступен только на компьютере. Чтобы осознанно открыть его в своей локальной сети, задайте перед запуском в PowerShell:

```powershell
$env:FRONTEND_BIND = "0.0.0.0"
$env:PUBLIC_URL = "http://192.168.1.10:8080"
docker compose -f docker-compose.yml -f docker-compose.monitoring.yml -f docker-compose.react.yml up -d --build --wait
```

Замените IP на адрес своего компьютера. Сначала откройте /health с телефона. Сеть должна разрешать связь между устройствами; правила брандмауэра и VPN не изменяются автоматически. Для Android endpoint должен указывать на тот же доступный адрес; после изменения параметров пересоберите debug APK. Публичное размещение требует отдельной подготовки HTTPS и секретов, описанной в аудите.

## Устройство

| Компонент | Назначение |
|---|---|
| frontend | Собранные HTML/CSS/JS и HTTP-шлюз к API и Grafana; Node без npm-зависимостей в runtime |
| app | Express, сеансы, CSRF, права владельца, приём SDK, экспорт и защищённый шлюз Grafana |
| db | ClickHouse, продуктовые события |
| dashboard | Продуктовая Grafana с разделением владельцев |
| prometheus | Служебные метрики |
| monitoring-dashboard | Отдельная Grafana оператора |

В frontend нет ключей БД и административных паролей. Сеанс находится в HttpOnly cookie. Полный ключ отправки приходит один раз в JSON-ответе создания/замены и живёт только в памяти текущего экрана; не сохраняется в URL, history state, localStorage или sessionStorage. Тематическая настройка хранится отдельно и не содержит учётных данных.

## API кабинета

Все адреса начинаются с /api/console. Ответы private, no-store. Чтение чужого ресурса возвращает 404; отсутствие сеанса — JSON 401. Приём событий SDK остаётся /api/v1/events без изменения контракта.

| Метод и путь | Действие |
|---|---|
| GET /session | Публичные настройки, пользователь и CSRF-токен для текущей cookie |
| GET /guide | Примеры подключения без ключей |
| POST /register, /login, /logout | Сеанс кабинета |
| GET, POST /projects | Список и создание |
| GET /projects/:id | Проект и приложения |
| POST /projects/:id/settings | Название и архив |
| POST /projects/:id/apps | Создание приложения и одноразовый ключ |
| GET /apps/:id | Приложение и маски ключей |
| POST /apps/:id/keys/rotate | Замена |
| POST /apps/:id/keys/:keyId/revoke | Отзыв |
| GET /apps/:id/statistics | Параметры защищённой Grafana |
| POST /apps/:id/test | Серверное тестовое событие |

POST требует JSON и действующий csrfToken. Тело ограничено 12 КиБ. Ограничения входа и изменений общие с прежними HTML-формами. TypeScript не заменяет проверки сервера.

В React Compose API доверяет ровно одному внутреннему proxy hop. Frontend удаляет присланные клиентом Forwarded/X-Forwarded-* и устанавливает собственные значения; API не имеет опубликованных портов. При иной топологии прокси требуется пересмотреть доверие и проверки, а не выставлять trust proxy без ограничения.

## Мониторинг и испытания

Frontend имеет отдельный /frontend-health. API проверяет его для ulsa_frontend_available; правило UlsaFrontendUnavailable обнаруживает отказ дольше минуты. Это проверка процесса раздачи статики, а не замена проверкам БД и API. В React Compose добавлена версия конфигурации правил: при переходе Prometheus пересоздаётся и перечитывает файл. При последующем изменении правил версию нужно обновлять либо явно перезагружать Prometheus.

Текущие результаты 0.12.0 — [LAB5_CHECKLIST.md](LAB5_CHECKLIST.md). Исторические проверки переноса кабинета — [REACT_QA_2026-11-03.md](REACT_QA_2026-11-03.md). Android/iOS-код этим переносом не изменяется. Публикация Kotlin в Maven, JavaScript в npm, iOS-адаптер и расширенная авторизация остаются отдельными этапами.

## Удаление приложения

Внизу страницы приложения доступна кнопка удаления с подтверждением точного идентификатора. Удаляются выбранное приложение, его ключи, панель и события; соседние приложения и сам проект сохраняются. При прерывании можно завершить удаление повторно. [Инструкция, миграция и проверки](APPLICATION_DELETION.md).

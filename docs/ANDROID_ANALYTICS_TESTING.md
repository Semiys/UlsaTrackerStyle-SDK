# Проверка UlsaTracker в «Доме Коллекционера»

Продуктовая аналитика включается только в настроенной debug-сборке Android. Общие экраны вызывают интерфейс `ProductEventTracker`, Android-адаптер передаёт события библиотеке UlsaTracker 0.2.0. Без локальной SDK и в release используется пустой адаптер. Рабочего адаптера iOS пока нет.

## Локальная страница подключения

Версия 0.9.0 содержит кнопку «Инструкция по подключению» и страницу `http://localhost:8080/guide`. Опубликованный выпуск запускается с `docker-compose.yml` и `docker-compose.release.yml`; для разработки добавьте `docker-compose.dev.yml`. Корневой Compose без override сохраняет учебный образ 0.0.4 с сервером 0.7.5.

## С чего начать прямо сейчас

29.10.2026 обновлённая debug-сборка уже установлена на TECNO. Сервер, ClickHouse и Grafana запущены. Ключ приёма уже задан, endpoint APK — `http://192.168.0.90:8080`. Для первого теста не нужно менять `local.properties`, снова регистрироваться или пересобирать приложение.

1. Оставьте ноутбук включённым и подключённым к вашей домашней Wi-Fi сети. Docker Desktop должен работать.
2. На TECNO включите Wi-Fi и подключитесь к той же сети. Пока проверяете локальный адрес, не переключайте телефон только на мобильный интернет.
3. Откройте на телефоне «Дом Коллекционера» — установленную debug-сборку, а не APK, заново скачанный из магазина. Если открыта форма или параметры и нижние вкладки не видны, вернитесь кнопкой «Назад» до основного экрана.
4. На ноутбуке откройте `http://localhost:8080/dashboard`.
5. Начните с трёх переходов, описанных ниже. USB можно отсоединить: текущий APK отправляет данные по Wi-Fi.

Это проверка текущего демонстрационного проекта. Если создать отдельный проект в кабинете, нужно будет заменить ключ внутри APK и смотреть панель именно нового приложения. Не смешивайте эти два варианта в первом тесте.

## Где смотреть результат в Grafana

Панель открывается в браузере ноутбука. Нажмите «Период»: для свежих действий выберите **Последние 5 минут** и «Применить»; для общей проверки начните с **Последние 7 дней**; при необходимости обновите страницу через 45–60 секунд после действий на телефоне. SDK отправляет пакетами, а Grafana обновляется раз в 30 секунд, поэтому запись не обязана появляться мгновенно.

Нужны три участка панели:

| Участок | Для чего смотреть |
|---|---|
| Счётчик «Нажатия кнопок» вверху | Общее количество событий `button_click` за период. |
| Таблица «Нажатия кнопок» ниже графиков | Конкретная кнопка, экран, на котором её нажали, и число нажатий. В таблице до 100 сочетаний. |
| «Последние 50 событий · весь период хранения» внизу | Проверка свежего события по времени, платформе Android, версии приложения, экрану и свойствам. Эта таблица не ограничивается выбранными 7 днями. |

«Открытия экранов» и «Успешные действия» показываются отдельно. Поэтому общий счётчик «События» увеличивается сильнее, чем число нажатий: переход обычно создаёт клик и посещение следующего экрана. Три перехода обычно дают 3 нажатия и 3 открытия, а не всего 3 события. В одном пакете могут дополнительно приехать более ранние действия. Сравнивайте время совершения и время поступления: обновление Grafana само по себе не создаёт событий в Android-приложении.

Время поступления в журнале и подписи графиков показываются в **часовом поясе устройства**. Его название видно над панелью. Для Астрахани пересчитывать часы вручную больше не нужно. Пакеты SDK и исходный JSON API по-прежнему используют UTC. Само событие содержит время действия, а сервер отдельно сохраняет время приёма — после отсутствия связи они могут заметно различаться.

До проверки уже были тестовые события. Не ожидайте нулей: запишите исходное число и сравнивайте увеличение нужной строки.

## Первый тест: три нажатия без изменения коллекции

Сначала откройте вкладку «Дом» и подождите минуту, чтобы ранее накопленные события успели отправиться. Затем запишите текущий счётчик «Нажатия кнопок» в панели. После этого выполняйте последовательность по одному нажатию:

| Шаг на телефоне | Ожидаемое имя кнопки | Экран клика | Следующее посещение |
|---|---|---|---|
| На вкладке «Дом» нажмите «Статистика» | `tab_stats` | `collection` | `stats` |
| На вкладке «Статистика» нажмите «Профиль» | `tab_profile` | `stats` | `profile` |
| На вкладке «Профиль» нажмите «Дом» | `tab_collection` | `profile` | `collection` |

После третьего нажатия подождите 45–60 секунд и обновите панель на ноутбуке.

При отсутствии других действий ожидается **увеличение счётчика кликов на 3**. У соответствующих сочетаний кнопки и экрана должно прибавиться по одному нажатию. Дополнительно появятся события `screen_view` трёх посещённых разделов.

Если перед началом приложение запускалось заново, отдельное открытие начального экрана тоже может попасть в журнал. Оно увеличивает посещения, но не клики. Если параллельно пользуется приложением другой тестовый клиент этого проекта, общий счётчик может вырасти больше — сверяйте конкретные строки и время.

Наиболее понятный признак настоящего события телефона: `platform = android`, версия `1.5`, нужное имя экрана, а в свойствах — например, `{"button":"tab_stats"}`. Кнопка «Отправить событие» на самом сайте проверяет другой сценарий; для этой проверки её не нажимайте.

## Проверка отдельных функций

Проходите по одной группе и сверяйте результат после неё. Имена в таблицах — технические обозначения для аналитики, на телефоне кнопки остаются с обычными русскими подписями.

### Коллекция, поиск и фильтры

1. Откройте «Дом».
2. Откройте поиск и затем закройте его. На каждое нажатие ожидается `toggle_search` на экране `collection`.
3. Откройте фильтры: ожидается `toggle_filters`. Закрытие этой же кнопкой тоже считается нажатием.
4. Откройте выбор категории — `open_category_filter`. Выберите категорию — `filter_category`. Выбор «Все категории» — `all_categories`.
5. Откройте сортировку цены — `open_price_sort`. Выберите вариант — `sort_price`.
6. Выберите тег — `filter_tag`. Если есть кнопка сброса фильтров, нажмите её — `clear_filters`.
7. Переключите сетку и список — `view_grid` и `view_list`.

Строка поиска и названия ваших тегов/категорий не должны появляться в свойствах. Их ввод сам по себе не создаёт клик на каждый символ. Пустой список после фильтра не означает ошибку SDK — это результат выбранного фильтра.

### Карточка предмета и форма добавления

1. Нажмите существующий предмет: ожидается `open_model` на `collection`, затем посещение `model_detail`.
2. Нажмите «Изменить» и вернитесь без сохранения: `edit_model`, посещение `edit_model`, затем возврат в карточку. События успешного сохранения быть не должно.
3. При желании проверьте «Поделиться»: ожидается `share_model`. Отправлять данные кому-либо для проверки не требуется — системное меню можно закрыть.
4. На «Доме» нажмите кнопку добавления: `add_model`, затем посещение `add_model`. Вернитесь без сохранения. Нового предмета и `action_success` быть не должно.

Для проверки сохранения используйте **тестовый предмет**, чтобы не менять личную запись:

1. Откройте добавление и оставьте какое-нибудь действительно обязательное поле незаполненным. Обязательность зависит от выбранного шаблона.
2. Если кнопка сохранения доступна, нажмите её. Ожидается `save_model`, сообщение валидации и отсутствие `action_success`. Если кнопка недоступна, она не должна вызывать клик.
3. Заполните требуемые поля и сохраните тестовый предмет. Ожидается клик `save_model`, затем `action_success` со свойством `{"action":"model_saved"}` и ровно один новый предмет в коллекции.
4. Откройте этот тестовый предмет, измените поле и сохраните. Ожидается `save_model` на экране `edit_model`, затем `action_success` со свойством `{"action":"model_updated"}`. Второй предмет создаваться не должен.

Успех — это подтверждённая запись предмета в БД. Он не должен появляться только от открытия формы, отмены или неудачной валидации. Название/цена тестового предмета в аналитике не передаются.

### Фотографии

На тестовом предмете или в новой форме:

- Открыть блок фото — `open_photo` (в отдельных общих кнопках — `select_photo`).
- В листе действий выбрать «Сделать фотографию» — `take_photo`.
- Выбрать «Выбрать из галереи» — `choose_photo`. Отменить системный выбор разрешается: нажатие кнопки приложения уже произошло, но файл не добавится.
- В просмотрщике выбрать миниатюру — `select_photo_thumbnail`.
- Сделать фото обложкой — `set_photo_cover`.
- Запросить удаление — `request_delete_photo`; отменить — `cancel_delete_photo`; подтвердить удаление тестового фото — `confirm_delete_photo`.
- Закрыть просмотр — `close_photo_viewer`.

Системные кнопки камеры и галереи находятся вне интерфейса приложения и не отслеживаются этой интеграцией. В базу аналитики не отправляются изображения, пути и имена файлов. Проверку реального удаления выполняйте только на тестовом фото.

### Резервные копии

Этот блок можно оставить на второй проход. Для первичной проверки связи он не нужен.

1. В профиле открыть экспорт — `export_collection`. Сохранение ZIP проверяет отдельную функцию резервного копирования; в аналитику архив не передаётся.
2. Открыть импорт — `import_collection`. Системный выбор файла можно отменить. Реальный импорт добавляет записи в коллекцию, поэтому для него нужен подготовленный тестовый архив.
3. Открыть «Яндекс Диск» — `open_disk_backups`, экран `disk_backups`.
4. Для уже подключённого Диска: обновить список — `refresh_backups`; начать создание копии — `create_disk_backup`.
5. Открыть восстановление/удаление тестовой копии и отменить диалог. Подтверждать операции над личными архивами для проверки кнопок не требуется.
6. При использовании автоматических копий: включение/выключение — `toggle_auto_backup`, выбор периода — `select_backup_interval`.

У аналитики сейчас есть отдельный успех только для сохранения/редактирования предмета. Не ожидайте `action_success` от каждой настройки или операции резервного копирования: наличие `button_click` подтверждает нажатие, а результат самой операции проверяется в её интерфейсе.

## Проверка без USB и при недоступном сервере

### Без USB

1. Убедитесь, что первые три перехода уже появились на панели.
2. Отключите USB-кабель, оставив Wi-Fi телефона включённым.
3. На «Доме» один раз откройте поиск и один раз закройте его.
4. Через минуту в строке `collection` / `toggle_search` должно прибавиться 2 клика.

Если этот сценарий проходит, USB не участвует в транспортном пути SDK.

### Сервер временно выключен

1. На телефоне откройте «Дом», подождите минуту и запишите текущие числа кликов.
2. На ноутбуке остановите только приложение сервера:

```powershell
Set-Location 'D:\MyTracer SDK CopyStyle'
docker compose stop app
```

3. На телефоне выполните «Статистика», «Профиль», «Дом» по одному разу. Приложение должно продолжать работать. Панель сайта в это время может быть недоступна — это ожидаемо при остановке `app`.
4. Верните сервер:

```powershell
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d --build --wait
```

5. Вернитесь в приложение на телефоне и подождите до двух минут с учётом повторных отправок. Обновите панель ноутбука.
6. У трёх нужных сочетаний кнопки и экрана должно прибавиться по одному клику. Повторное обновление панели без действий не должно снова прибавлять эти три клика.

SDK имеет ограниченную очередь: по умолчанию до 1000 событий и срок хранения 7 дней. Для короткой проверки достаточно нескольких переходов; бесконечное хранение всех нажатий не предусмотрено.

## Если событие не появилось

Проверяйте по порядку — от сети к ключам:

1. **На ноутбуке открывается сайт?** Проверьте `http://localhost:8080/health`. В текущем стенде ожидаются `status: ok`, `version: 0.9.0`, `storage: clickhouse`. Если страница не открылась, сначала запустите Docker Desktop и `docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d --build --wait`.
2. **Телефон видит ноутбук?** Откройте в браузере телефона `http://192.168.0.90:8080/health`. Если ответ не появился, SDK также не сможет обратиться к серверу по этому адресу.
3. **Сеть та же?** Мобильный интернет и гостевая Wi-Fi сеть могут не иметь доступа к домашнему ноутбуку. Для этого теста подключите оба устройства к одной обычной Wi-Fi сети.
4. **IP не поменялся?** В PowerShell выполните `ipconfig`. Ищите IPv4 адаптера «Беспроводная сеть», подключённого к вашему роутеру. Не выбирайте адрес WSL, Docker или VPN. Если адрес изменился, обновите endpoint в `local.properties`, пересоберите и установите APK.
5. **VPN не перехватывает локальную сеть?** Если используете VPN/прокси, проверьте, разрешён ли доступ к локальным адресам. Повторите открытие `/health` с телефона. Брандмауэр целиком отключать не нужно; для диагностики важен доступ к Docker/порту 8080 в частной сети.
6. **Установлена нужная сборка?** Версия из магазина/release не отправляет эту тестовую аналитику. Установите подготовленный debug APK без удаления приложения. На текущем TECNO он уже установлен.
7. **Смотрите нужный проект?** Текущий APK отправляет в демонстрационный проект. Ключ созданного вами отдельного Android-приложения начинает использоваться только после замены ключа и пересборки APK; события этого приложения смотрят в его собственной статистике.
8. **Нажатие действительно произошло?** Выберите простую доступную кнопку вкладки. Недоступная кнопка, прокрутка и ввод текста не обязаны создавать `button_click`.
9. **Была задержка?** В нормальном режиме подождите минуту; после отсутствия связи — до двух минут. Обновите страницу и проверьте время в последних событиях, учитывая часовой пояс панели.

Если `/health` открывается и на телефоне, но событий всё равно нет, для диагностики достаточно: какие действия выполнены, время, адрес endpoint, ответ `/health` и открыта ли демопанель или приложение кабинета. API-ключ и весь `local.properties` в чат присылать не нужно.

Диагностика контейнеров, без удаления данных:

```powershell
Set-Location 'D:\MyTracer SDK CopyStyle'
docker compose ps
docker compose logs --tail 80 app
```

Если PowerShell не находит `docker`, откройте новое окно после установки Docker Desktop. На этом ноутбуке ту же команду можно вызвать полным путём:

```powershell
& 'C:\Users\sauro\AppData\Local\Programs\DockerDesktop\resources\bin\docker.exe' compose ps
```

## Как записывать результаты

Можно вести короткий список в любом текстовом файле:

```text
Время: 15:10 по Астрахани
Действие: Дом — Статистика — Профиль — Дом, по одному нажатию
До: кликов 20
После: кликов 23
Строки: tab_stats/collection +1; tab_profile/stats +1; tab_collection/profile +1
USB: отключён; Wi-Fi: одна сеть с ноутбуком
Итог: успешно
```

Для ошибки добавьте ожидаемый и фактический результат: например, «нажал один раз, в нужной строке прибавилось 2» или «/health открывается на ноутбуке, но не на телефоне». Такой результат гораздо полезнее общего «не работает».

## Что собирается

- `screen_view`: посещение экрана. Повторная отрисовка, изменение поля и загрузка данных не считаются новым посещением.
- `button_click`: постоянное имя кнопки и имя экрана. Общий компонент сохраняет имя переданного действия и не создаёт второе событие.
- `action_success`: успешное создание/изменение предмета после записи в БД. Нажатие «Сохранить» и успешное сохранение — разные события.

Названия предметов, введённый текст, поисковые запросы, цены, заметки, содержимое/имена фотографий, пароли и OAuth-токены не передаются. Состояние пользовательского списка не отправляется. Имена действий заданы в коде; неизвестная подпись кнопки заменяется постоянным безопасным именем.

В текущем доступном интерфейсе охвачены коллекция, карточка предмета, добавление и редактирование, фото, список желаний, достижения, статистика, настройки, шаблоны и поля, конфиденциальность, локальные и облачные резервные копии. Переключатели и пункты меню тоже считаются действиями. Динамические категории/теги и пользовательские поля объединяются по типу действия: их значения не отправляются.

Системная клавиатура, системный выбор файла, жест прокрутки и аппаратная кнопка Android не являются кнопками приложения. Переходы между карточками отражаются посещениями экрана. Недоступные в локальной версии экраны входа, подписки и редактирования сетевого профиля не входят в проверенное покрытие.

## USB, Wi-Fi и интернет

USB требуется только выбранному способу установки/отладки. Библиотека отправляет обычные HTTP(S)-запросы по сети, без ADB. Для установленного APK достаточно доступности сервера с телефона.

| Подключение | Endpoint в debug APK | Что нужно |
|---|---|---|
| Телефон и ноутбук в одной Wi-Fi сети | `http://192.168.0.90:8080` | Работающий Docker, доступ к порту 8080 в частной сети. IP ноутбука может измениться. |
| Телефон по USB с ADB reverse | `http://127.0.0.1:8080` | `adb reverse tcp:8080 tcp:8080`; повторить после переподключения. |
| Телефон через мобильный интернет/другую сеть | Например, `https://analytics.example.org` | Сервер с доступным HTTPS-адресом. Локальный адрес `192.168.*` из другой сети недоступен. |

Для локальной сети интернет как таковой не нужен. После установки APK можно отключить USB: пока телефон находится в той же доступной Wi-Fi сети, события продолжат передаваться. Отключение ноутбука делает сервер недоступным; SDK временно хранит события в ограниченной локальной очереди и повторяет отправку позже.

## Запуск на этом ноутбуке

1. Запустите Docker Desktop.
2. В PowerShell:

```powershell
Set-Location 'D:\MyTracer SDK CopyStyle'
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d --build --wait
```

3. Откройте на ноутбуке `http://localhost:8080/dashboard`. Текущая локальная проверка использует демонстрационный проект. Выберите период 7 дней и проверьте время события в последних записях; обновление панели занимает до 30 секунд.
4. Проверьте адрес ноутбука командой `ipconfig`. Телефон должен находиться в той же сети. Для этого теста использовались ноутбук `192.168.0.90` и телефон `192.168.0.250`.
5. В игнорируемом `local.properties` мобильного проекта:

```properties
ulsaTracker.sdkPath=D:/MyTracer SDK CopyStyle/sdk/kotlin
ulsaTracker.endpoint=http://192.168.0.90:8080
ulsaTracker.ingestKey=ПОЛНЫЙ_КЛЮЧ_ПРИЁМА
```

Не заменяйте остальные строки файла. Для отдельного приложения создайте проект и Android-приложение в кабинете сервера и возьмите его ключ приёма. Тогда статистику нужно открывать внутри этого приложения в кабинете. Ключ чтения в APK не добавляется. После смены адреса или ключа APK нужно пересобрать.

6. Сборка и установка на подключённый TECNO:

```powershell
Set-Location 'D:\AndroidDekstops\DomCollection'
.\gradlew.bat --gradle-user-home 'D:\AndroidProjectGradle\DomCollectionGradle' '-Dorg.gradle.java.home=D:/ProgramsCity/jbr' :androidApp:assembleDebug --offline --max-workers=2
& 'D:\sdkad\platform-tools\adb.exe' -d install -r 'androidApp\build\outputs\apk\debug\androidApp-debug.apk'
```

Пути и номер телефона относятся к этому ноутбуку. На другом компьютере замените их. `install -r` обновляет совместимо подписанную debug-сборку, сохраняя данные; удалять приложение ради теста не нужно. APK также можно установить как файл без USB. HTTP разрешён только для локальной debug-проверки; публичный сервер подключается по HTTPS.

## Проверки вручную

Перед сценарием запишите текущие счётчики и смотрите приращения. Подождите до 60 секунд с учётом пакетной отправки SDK и обновления Grafana.

- [ ] Переходы «Дом», «Статистика», «Профиль»: по одному клику соответствующей вкладки, правильный исходный экран; посещение нового раздела.
- [ ] Поиск, фильтры, сортировка, сетка и список: отдельные имена действий. Сам текст запроса, тег и категория отсутствуют в свойствах.
- [ ] Карточка предмета: открыть, поделиться, изменить, добавить похожий, запросить/отменить удаление.
- [ ] Добавление/редактирование: проверка обязательных полей и клик сохранения; успех появляется только после фактического сохранения.
- [ ] Фото: камера, галерея, просмотр, миниатюра, обложка, запрос/отмена удаления. Не удаляйте личное фото ради проверки — используйте тестовый предмет.
- [ ] Желания: открыть список/карточку, добавить, изменить, закрепить, перейти к покупке, отменить удаление.
- [ ] Достижения: открыть список и карточку, закрепить/открепить доступную награду.
- [ ] Настройки: тема, палитра, плотность сетки/списка, шаблоны и пользовательские поля; корректный экран события.
- [ ] Конфиденциальность: открыть политику и изменить настройку диагностики. Сама диагностика остаётся отдельной функцией.
- [ ] Резервные копии: экспорт/импорт, открыть Яндекс Диск, обновить список, создать/восстановить копию, отменить операцию; подтверждения не запускаются автоматически.
- [ ] Без действий на экране счётчики кликов не растут. Недоступная кнопка не вызывает событие.
- [ ] Отключить USB, оставаясь в той же Wi-Fi сети: события приходят на ноутбук.
- [ ] Временно остановить сервер, выполнить несколько безопасных переходов, вернуть сервер: события догружаются без повторного учёта.
- [ ] Убедиться, что личные поля и файлы не появились в свойствах событий.

Экспорт, восстановление, удаление и изменение личной коллекции не нужны для короткой проверки подключения. Для них используйте тестовые данные/резервную копию.

val onAdd = rememberProductClick("add_model") {

## Календарь и переходы (сайт 0.9.0)

- Для всей истории нажмите «Период», выберите «За весь период» и «Применить». Будут показаны все сохранённые события выбранного приложения без ограничения в 366 дней. Выбор сохраняется при обновлении.
- Нажмите «Период», выберите «Последние 5 минут» и «Применить». Выполните на телефоне несколько действий, дождитесь доставки SDK и обновления Grafana (обычно до минуты). События должны появиться в счётчиках и динамике.
- Перезагрузите страницу, нажмите «Обновить панель» и смените тему: выбранный период сохранён. Для ручного диапазона даты остаются фиксированными; быстрые варианты движутся вместе с текущим временем.
- Проверьте календарь: две даты, ручной ввод местного времени устройства, «Применить» и «Отменить». На телефоне виден один месяц, на компьютере — два. Максимум — 366 дней; неверная дата и будущее окончание отклоняются.
- Проверьте 1 час, 24 часа, 7/30/90 дней. Шаг динамики меняется от секунд и минут до часов и дней. Предыдущий период всегда имеет ту же длительность и непосредственно предшествует выбранному.
- События фильтруются по времени действия. Если за последние пять минут ничего не происходило, пустой результат верен, даже когда старые события есть в базе. Таблица «Последние 50 событий · весь период хранения» намеренно показывает весь доступный журнал.
- Вместо карты активности найдите «Переходы между экранами». Три перехода из первого теста должны добавить по одному к `collection` / `stats`, `stats` / `profile`, `profile` / `collection`. Оба посещения должны попасть в выбранное окно и одну сессию; общий счётчик кликов при этом проверяется отдельно.

Подробные правила и полный чеклист: [DATE_RANGE_AND_TRANSITIONS.md](DATE_RANGE_AND_TRANSITIONS.md) в серверном проекте.

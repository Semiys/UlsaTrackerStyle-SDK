# Календарь и переходы между экранами — 0.8.3

При первом открытии без сохранённого периода показывается «Текущий день»: с местной полуночи устройства до текущего момента. Ранее выбранный период в адресе страницы сохраняет приоритет.

В панели один выбор периода: кнопка «Период» над Grafana. Встроенный выбор времени Grafana скрыт, чтобы обновление и смена темы не сбрасывали другой фильтр.

## Как выбрать время

1. Откройте статистику нужного приложения или демонстрационную панель.
2. Нажмите «Период». На компьютере видны два месяца, на узком экране — один.
3. Нажмите дату начала, затем дату окончания. Можно ввести даты и время вручную в формате `ДД.ММ.ГГГГ ЧЧ:ММ:СС`, включая миллисекунды при необходимости.
4. Даты вводятся в часовом поясе устройства. Он указан рядом с календарём, например `Europe/Astrakhan · UTC+04:00`. Пересчитывать часы вручную не нужно.
5. Нажмите «Применить». «Отменить», Escape и нажатие снаружи окна оставляют прежний период.

Быстрые варианты: «За весь период», 5/15/30 минут, 1/3/6/12/24 часа, текущий местный день, 2/7/30/90 дней. «Последние 7 дней» означает скользящие семь суток до текущего момента. Ручной диапазон остаётся фиксированным; он не сдвигается при обновлении. Выбор сохраняется в адресе страницы, включая ссылку «На весь экран».

Для ручного выбора нельзя задать окончание в будущем, окончание раньше начала или интервал больше 366 дней. Это ограничение просмотра, а не обещание хранения данных за весь такой срок. Первый и последний день могут быть неполными. Сравнение использует непосредственно предыдущий отрезок точно такой же длительности; событие на общей границе относится к текущему отрезку.

Часовой пояс определяется браузером, без запроса геолокации. В базе и пакетах SDK остаются моменты времени UTC. Фиксированный диапазон в ссылке сохраняет те же моменты при открытии на устройстве другого часового пояса, а подписи показывают их местное время. «Текущий день» и дневные интервалы графиков используют местную полночь.

При переводе часов длина календарного дня может отличаться от 24 часов. Несуществующее местное время не принимается. Для повторяющегося осеннего часа поле содержит смещение, например `01.11.2026 01:30:00 -05:00`, чтобы два разных момента не смешивались. Относительные «24 часа»/«7 дней» сохраняют реальную длительность; сравниваемый предыдущий отрезок имеет точно такую же длительность.

## За весь период

Первый пункт списка показывает все сохранённые события выбранного приложения, начиная с первого события и до текущего момента. Ограничение ручного диапазона в 366 дней к нему не применяется. В полях показаны «С первого события» и «Текущий момент». Чтобы перейти к ручному диапазону, выберите даты в календаре.

Начало вычисляется отдельно для приложения с проверкой прав владельца. При отсутствии событий график остаётся пустым. Выбор сохраняется после перезагрузки, обновления и смены темы. Фоновая проверка учитывает поздно пришедшие события с более ранней датой, не перезагружая Grafana при неизменном начале истории. Предыдущий отрезок до первого события не содержит данных, поэтому его линия сравнения будет нулевой.

- [ ] Выбрать «За весь период» и «Применить»: видна вся доступная история, включая события старше 90 дней.
- [ ] Обновить страницу и сменить тему: пункт остаётся выбранным, новые события добавляются.
- [ ] Проверить новый проект без событий: пустой результат без ошибки или выдуманной записи.

## Что заменило карту активности

Таблица «Переходы между экранами» отвечает на вопрос, какие разделы люди открывают друг за другом. Столбцы: исходный экран, следующий экран, число переходов и доля среди всех переходов выбранного периода. Показываются 15 наиболее частых сочетаний; знаменатель доли учитывает также остальные сочетания.

Считаются последовательные `screen_view` одной сессии. Между ними могут быть клики: они не прерывают последовательность экранов. Оба посещения должны попасть в выбранный период. Повторное посещение того же экрана подряд не создаёт перехода. Пустое имя экрана прерывает связь, а события с одинаковым временем не упорядочиваются предположительно. Повторы одного `event_id` не увеличивают результат.

Пример: посещения `collection`, `stats`, `profile` дают два перехода: `collection` / `stats` и `stats` / `profile`. Это число переходов, а не уникальные пользователи, клики или воронка достижения цели. Одно посещение без следующего экрана не создаёт строку.

Для таблицы выбранный период имеет смысл: она показывает маршруты именно этого интервала. При пяти минутах без пар посещений пустой результат корректен. Таблица «Последние 50 событий · весь период хранения» внизу по-прежнему показывает весь доступный журнал и не подчиняется этому фильтру.

## Что проверить вручную

- [ ] Открыть статистику без параметров: выбрано «Текущий день», начало — 00:00 по устройству, показан его часовой пояс.
- [ ] Открыть «Период», выбрать две даты и местное время; применить и проверить подпись, счётчики и график.
- [ ] Обновить страницу и сменить тему: выбранные даты не изменились.
- [ ] Выбрать «Последние 5 минут»: свежие действия видны после доставки SDK, старые исключены. При автоматическом обновлении окно движется.
- [ ] Отменить другой выбор: прежний фильтр остался.
- [ ] Ввести неверную дату, окончание раньше начала, будущее окончание и более 366 дней: появляется понятная ошибка, старый фильтр не меняется.
- [ ] На телефоне проверить один месяц, прокрутку, поля времени и доступность кнопок «Отменить»/«Применить» в обеих темах.
- [ ] В одной сессии Android выполнить «Дом», «Статистика», «Профиль», «Дом». После доставки найти переходы `collection` / `stats`, `stats` / `profile`, `profile` / `collection` с прибавлением по одному при отсутствии других действий.
- [ ] Повторить посещение того же раздела: перехода экрана в самого себя нет. Для проверки отдельного нажатия использовать таблицу кнопок, а не переходов.
- [ ] Открыть «На весь экран»: там тот же период и тема, второго выбора времени нет.

# JavaScript SDK 0.1.0

Явная отправка событий Web в UlsaTrackerStyle SDK. Поддерживаются современные браузеры с Fetch, Web Crypto, TextEncoder и AbortController. Сбор всех кликов, содержимого форм, URL, фотографий и рекламных идентификаторов автоматически не выполняется.

## 1. Подготовьте приложение

В кабинете создайте проект, затем Web-приложение. В origin укажите точный адрес сайта: протокол, домен и порт, без пути. Например, `https://example.com` или `http://localhost:8080`. Полученный ключ показывается один раз. Ключ отправки в браузере доступен посетителю; это не пароль кабинета и не ключ просмотра статистики.

## 2. Подключите одним из способов

Обычный HTML:

```html
<script src="https://analytics.example.com/sdk/ulsa-tracker.js"></script>
<script>
const tracker = UlsaTracker.create({
  endpoint: 'https://analytics.example.com',
  ingestKey: 'ВАШ_КЛЮЧ_ОТПРАВКИ',
  appVersion: '1.0.0'
});
tracker.screen('home');
document.querySelector('#save').addEventListener('click', () => {
  tracker.click('save', 'home');
});
</script>
```

ES module из развёрнутого сервиса:

```javascript
import { createTracker } from 'https://analytics.example.com/sdk/index.mjs';
const tracker = createTracker({ endpoint: 'https://analytics.example.com', ingestKey: 'ВАШ_КЛЮЧ_ОТПРАВКИ', appVersion: '1.0.0' });
```

Локальный npm-пакет для сборщика сайта:

```bash
npm install /путь/к/UlsaTrackerStyle-SDK/sdk/js
```

```javascript
import { createTracker } from '@semiys/ulsa-tracker';
```

Пакет не опубликован в npm. Настройка `private: true` защищает от случайной публикации. Установка по имени из публичного реестра пока не заявляется. Зависимостей у SDK нет. Для локального HTTP явно задайте `allowHttp: true`; для публичного сайта используйте HTTPS. CSP сайта должен разрешать скрипт и запросы к вашему адресу аналитики.

## 3. Отмечайте события

```javascript
tracker.screen('collection');
tracker.click('add_model', 'collection');
tracker.track('action_success', { screen: 'add_model', properties: { action: 'model_saved' } });
await tracker.flush();
console.log(tracker.getStatus()); // без ключа и содержимого очереди
tracker.setCollectionEnabled(false); // очистка очереди и сохранение отказа
tracker.close(); // остановка таймеров и обработки жизненного цикла
```

`track`, `screen`, `click` возвращают приём события в очередь, не подтверждение сервера. `flush` запрашивает отправку и возвращает диагностику; лимиты и паузы не обходятся повторными вызовами. Методы не выбрасывают сетевые ошибки в пользовательский обработчик.

## Доставка и ограничения

- По умолчанию очередь находится в памяти. Для локального сохранения неотправленных событий задайте `persist: true`; это отдельное решение интегратора о хранении данных на устройстве посетителя. Недоступное хранилище не мешает работе памяти.
- Очередь по умолчанию до 500 событий, настраивается до 1000; при переполнении удаляются старые. Неотправленные события старше 7 суток удаляются.
- Пакеты до 20 событий и 60 КБ, по таймеру 30 секунд, при заполнении и уходе страницы в фон. Гарантии завершения запроса при закрытии браузера нет.
- Удаление после полного корректного ACK. Потерянный ответ сохраняет ID; повтор не должен увеличивать логический счётчик сервера.
- Сеть/5xx/429: пауза с учётом Retry-After и до трёх попыток за цикл. `flush` не обходит cooldown. 401/403 приостанавливает отправку; после исправления ключа создайте новый экземпляр. Непринимаемые события 400/409 учитываются в `rejected`.
- Выключение запрещает новые события, очищает очередь, отменяет текущую отправку и сохраняет выбор. Уже принятые сервером события не отзываются. SDK не запрашивает согласие вместо интерфейса вашего приложения: включайте её согласно выбранным пользователем настройкам.
- Сеанс общий для вкладки и экземпляра подключения, обновляется после 30 минут без новых событий. Это не количество уникальных людей.
- Не вызывайте несколько экземпляров для одного ключа с общей постоянной очередью: блокировка между вкладками в этой версии не реализована. Изолируйте очередь или оставьте стандартное хранение в памяти.

Для проверки откройте `/sdk-demo` на сервере, создайте Web-приложение с origin этого адреса и используйте его ключ. Затем откройте статистику приложения. Демонстрация отправляет реальные тестовые события.
